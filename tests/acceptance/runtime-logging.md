# 平台及插件持久运行日志验收

本单验收平台启动与结束、插件日志接纳、落盘、历史查询及故障恢复。L1 至 L7 可通过直接调用公开服务、真实模块及独立进程执行，可以在界面改版前完成。U7 另行验证成品 UI 的跳转体验。各项当前状态为待实施、待实测。[日志系统工作单](../../docs/runtime-logging-plan.md) · [UI 专项验收](ui-runtime-feedback.md)

## 准备

使用专用临时目录、合成 PDF、合成笔记、可辨识的操作与测试标记。记录运行包、SDK 与模块散列、PID、运行 ID、工作区、归档分片、事件和关联操作 ID。保留写入调用结果、关闭终态、原始归档、查询期望集合、实际结果和退出码。故障注入只作用于测试目录或专用写入器。用真实权限拒写验证文件边界，用可控短写或空间不足复现部分写入，并标明复现方式。执行人逐项记录通过／失败及实际覆盖。

## 用例

| 编号 | 操作 | 通过条件及证据 |
|---|---|---|
| L1 跨进程与启动 | A 启动并激活真实文献阅读插件，尝试导入缺少 PDF 文件头的合成文件，记录这次拒绝操作的事件 ID 并正常关闭。B 用同一工作区查询 A 的该事件。另以损坏 manifest 启动至装载失败。 | 两个进程有独立运行 ID。B 能按事件 ID 查到 A 的坏 PDF 原因、错误码、插件来源与版本，并能查到正常退出及最后清理事件，结果与原文件一致。损坏模块尚未激活时，平台仍记录准确失败阶段与原因。给出 PID、终态、事件 ID、归档和 B 查询结果。 |
| L2 事务、发布与通知镜像 | 用已有发布组机制交错写即时记录、暂缓记录和通知，分别提交及撤销，在发布前后多次查询。 | 撤销的内容及通知镜像均不对外可见，原始归档也无其负载。只有被撤销记录的通道不会出现在来源列表。较小的来源序号可以延迟提交，最终准确出现一次，刷新或订阅重连不会多写。一条通知只有一条关联持久镜像。核对事件集合，允许已保留但随后撤销的来源序号形成空洞。 |
| L3 写入故障、背压与关闭 | 生成 10 万条有唯一标识的合成记录，注入真实不可写目录及短写或空间不足，持续写到有界队列溢出后恢复。制造配置冲突而取消关闭，再次写入并正常关闭。另在持续输出时关闭。 | 用提交结果、归档事件集合、已报告的拒绝／丢弃数或未确认区间逐项对账。记录队列峰值、峰值内存和生产速率。宿主持续响应，写入故障公开一次持续状态，设备故障处理无递归写入。恢复后可写，取消关闭后仍有新记录。成功关闭返回时写入线程已 join，最终记录可读，结束状态与实际退出一致。 |
| L4 来源、原生级别与兼容 | 装载原 P7 Qt 插件、合成 Native 五级日志插件及新版阅读器，写入边界长度、超限内容、失效 Context 和同名通道。用缺必需 SDK 或不匹配配置构建／装载消费者。 | 旧 Qt 模块原二进制可运行。Native 的 TRACE、DEBUG 以及其余合法级别和大于 4096 字节的合法消息保真。各入口按原契约拒绝其超限值和失效身份，保留原返回码。来源取自受信宿主，两个插件同名通道可以区分，无法伪装平台记录。不兼容项给出具体诊断。 |
| L5 轮转、并发及异常完整性 | 调低测试轮转／保留阈值，两个进程并发写同一工作区。关闭其一并清理过期历史。模拟异常中止，在测试副本尾部构造半行。 | 各进程写入目录独立，轮转边界之前和之后的完整事件均可读。清理跳过仍在写的会话，删除范围限定在日志归档根内。已清理事件有明确查询状态。异常运行不标为正常退出，完整行仍可读，损坏尾部可报告，原件可复核。记录清理前后会话、文件与 SHA。 |
| L6 历史查询、顺序与导出 | 写入多运行、同一时间、多个来源、不同级别、跨分片事件及一条延迟提交的较小来源序号。按运行、来源、实例或代次、最低级别、关键词查询，以固定上界向前翻页并同时追加。断开订阅再续读，按 ID 定位与导出。 | 逐页合并结果，与独立生成的期望集合、顺序一致，无漏行／重复。运行、来源、版本、时间准确，游标、订阅断点及实时增量之间可对账。过期、空查询和读失败可区分。导出仅包含选定范围，只读查询与恢复筛选后，封闭分片 SHA 相同。 |
| L7 平台及插件业务采集 | 在支持多模块的宿主运行两个真实插件。在无可见窗口的测试宿主加载阅读器模块，用测试适配器调用保存按钮和命令共用的阅读器业务操作。覆盖成功及损坏 PDF 导入、渲染失败、保存成功与双进程冲突、导出及重试。植入可辨识的合成笔记、引文和凭据字段。 | 对照实际业务返回值和归档记录，按操作标识追溯平台装载、插件身份、错误码及恢复。未打开面板时短暂失败仍可读，单次失败与对应通知镜像可按标识核对。归档与筛选导出均不含植入内容及凭据。失败保留原业务文件与未保存草稿，核对恢复后的修订和实际结果。平台输出面板按来源和事件 ID 定位真实归档的体验由 U7 验证。 |
