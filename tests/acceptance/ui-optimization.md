## 启动

在当前本机已编译 Release 后，从仓库根目录 PowerShell 运行配置工作台：

```powershell
$env:PATH = "E:/Qt/5.15.2/msvc2019_64/bin;$env:PATH"
$env:QT_QPA_PLATFORM = 'windows'
& ./build/ela-msvc-release/bin/cordis_config_workbench.exe
$LASTEXITCODE
```

手动实例管理入口为同目录 cordis_ela_demo.exe，也需使用所用 Qt kit 的运行环境。其他机器按实际 Qt 5.15.2 MSVC kit 修改路径。需要测试保存/冲突时，用配置工作台 --file 指定独立验收文件，避免修改默认配置。

## 覆盖矩阵

| 维度 | 要求 |
|---|---|
| 入口 | cordis_config_workbench 与 cordis_ela_demo；分别覆盖配置管理和手动实例管理 |
| 主题 | 浅色、深色、运行中切换；控件/内容/选择状态均检查 |
| 尺寸 | 1200×800 常用逻辑尺寸、约 1000×600 窄窗口、约 1880×900 宽窗口；配置页面另沿用 900×600 布局检查 |
| 缩放 | 自动化覆盖 QT_SCALE_FACTOR=1 和 1.5；原生检查本机常用系统缩放与系统 150%，记录实际分辨率和可用工作区 |
| 原生边界 | 改变系统 DPI、跨屏切换要独立记录；无对应硬件时写未覆盖，进程 150% 不替代系统/跨屏证据 |
| 状态 | 空内容、活动、停止、加载/清理中、等待依赖、失败、旧身份撤销；配置含未应用、未保存、保存中、失败和冲突 |

窗口逻辑尺寸与屏幕物理尺寸分别记录；屏幕不足时使用最大可用尺寸，并注明未覆盖组合。常用/窄窗口完成完整操作，宽窗口重点检查内容分配和留白；高 DPI 重点检查文字、工具栏、卡片和拖动命中区域。

## 自动化与收口

已有检查的入口为 workbench、management、configuration_ui、configuration_management、ui_pages、ui_services 和 acceptance 相关 CTest。构建完成且已配置 Qt 运行环境后，可执行：

```powershell
ctest --test-dir build/ela-msvc-release -L ui --output-on-failure
```

仅将实际存在且覆盖对应行为的检查映射到场景；新增偏好存储/状态模型的测试在实现时补充，不预先填写通过。布局截图辅助检查，不能只靠像素相同判断交互正确，也不能只靠测试数量判断专项完成。

专项收口需 UI-00–06 的完成条件满足，适用 Debug/Release 回归通过，人工检查有明确结论。任何环境未覆盖项均登记影响和后续处理；涉及当前目标环境的关键问题不得隐藏为“通过”。基线结果见 UI-S0 验证记录，增量结果按 UI-S4 单独归档，不将规范建立登记为功能完成。
