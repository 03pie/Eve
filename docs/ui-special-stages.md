# UI 专项阶段

日期：2026-10-27。按用户“分析 VS Code 每一个 UI 结构，然后优化修改”“分成专项阶段”的要求建立。本文件管理专项阶段及阶段出口，原 UI-00–07 工作包范围继续保留，实时状态统一见 [开发进度](progress.md#ui-设计与优化专项)。

UI-S0 记录已经交付的基线；用户后续补充的结构优化进入 UI-S1–04。原先通过的自动化和人工确认继续有效，不直接代填后续新增交互的验收结果。

## UI-S1 分析结构清单

1. 标题栏、应用菜单、命令中心、前进后退、窗口与布局操作。
2. 活动栏主入口、选择/焦点/悬停、插件分组、底部设置入口。
3. 主侧栏、辅助侧栏、视图容器、视图标题工具栏、树/列表与空状态。
4. 中央工作区、页签、页签上下文菜单、页面动作、面包屑和内部导航。
5. 底部面板、面板页签、上下文工具、分隔条、关闭/恢复和输出。
6. 状态栏的全局/上下文信息、进度、通知与错误入口。
7. Quick Open、命令面板、建议列表、键盘选择和失效条目撤销。
8. Home/Welcome、插件展示、设置检索/分类、配置与偏好的边界。
9. 字体/图标/颜色、密度、焦点与快捷键、响应式布局、DPI 和状态反馈。
10. 分屏、拖出窗口、终端/调试/源码编辑专属区域的适用性及能力边界。

详细对应见 [VS Code UI 结构分析](vscode-ui-structure.md)。分析覆盖这些结构；产品实现依照实际业务和已确定约束落地，不增加无真实功能的入口。

## 阶段执行约定

每个阶段先列出明确修改，再完成可运行实现和针对性验证，最后更新本阶段结果。设计决定有变化时更新分析和验收映射，不只追加进度口号。遇到前一阶段遗留问题优先修复，并保留失败证据。

第一方持续采用 Ela 控件、Microsoft YaHei 应用字体及 ElaAwesome 图标。Qt 布局/模型作为基础设施；公开 SDK 不暴露 Ela 类型，Core 不增加 Qt/Ela 依赖。

插件资源树属于插件内部，活动栏单击直达中央页签；全部页签可关闭，空工作区保持空白；前进后退保留；Home 卡片仍仅展示状态和单个左右开关；底部/通知不主动展开。这些是阶段设计的输入条件。

专项阶段不重编号 P3/P4/P5。尚未实现的模块、ABI、驻留、受控替换不由 UI 阶段代替，也不作为可点击的空功能提供。
