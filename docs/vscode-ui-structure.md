# VS Code UI 结构分析与 Cordis 对照

日期：2026-10-27。对应 [UI-S1](ui-special-stages.md)，以 VS Code 官方界面与扩展 UX 文档为依据，并对照当前第一方实现。本文件的“改进”是 Cordis 的设计决定，不能理解为已实现或已验收；实际状态以开发进度和阶段验证为准。

## 分析依据

VS Code 将界面组织为容器与容器中的视图/操作，导航、内容、辅助输出和状态承担不同职责。主要区域及其关系见 [官方界面说明](https://code.visualstudio.com/docs/editing/getting-started/userinterface) 与 [UX 总览](https://code.visualstudio.com/api/ux-guidelines/overview)。Cordis 沿用工作台的职责分区，以 Ela 提供控件和字体。

## 贯穿各结构的规则

字体/图标/颜色保持 Ela；焦点、悬停、选择、禁用、忙碌和失败均需能区分。原生窗口与进程/系统缩放分别记录。新增上下文入口复用既有动作与生命周期门禁，避免独立维护另一套权限状态。

当前分析得到的优先增量为：页签上下文批量关闭、面板输出局部工具、设置页检索、通知历史显式入口。这些项目分别进入 UI-S2/UI-S3；此前用户对 Ela 基线和系统 150% 的确认不直接证明这些新交互已验收。

编辑器的终端/调试、分屏/拖出、AI 对话及账号/远程工作区等独立能力，需真实后端与生命周期设计。当前结构分析记录其位置和职责；产品入口仅随对应业务能力实际实现而增加。

## 阶段设计与验证映射

UI-S1 分析已完成；上述“当前实现”记录分析起点，实施结果另记阶段验证。UI-S2/UI-S3 优先落实四项有真实数据和操作对象的增量，其余结构沿用 UI-S0 的既有实现并纳入回归。

| 增量 | 行为约定 | 实现位置 | 验证入口 |
|---|---|---|---|
| 页签上下文菜单 | 关闭当前/其他/右侧/全部；仅作用于菜单打开时的页签代次。新页和关闭后重开的同名页不被旧菜单误关；关闭只隐藏视图，不停止插件或删除编辑内容 | workbench.cpp | optimization_tab_context / tab_snapshot / tab_reentry；UI-A21 |
| 面板局部工具 | 输出页显示复制和清空，命令页隐藏它们；复用全局 QAction。关闭面板保留内容，启动仍收起 | workbench.cpp | optimization_panel_tools；UI-A22 |
| 设置检索 | 本页按中英文关键词过滤外观/布局/快捷键分组；Ctrl+F 聚焦，Escape 清空；无结果有恢复提示，不变更偏好值或写盘 | workbench.cpp | optimization_settings_search / settings_reentry；UI-A23 |
| 通知历史入口 | 状态栏铃铛和“转到→通知历史”显式打开管理通知标签。级别和文本来自独立服务快照，未连接 Kernel 仍可回看；不自动打开底部、不渲染通知中的 HTML | workbench.cpp / pages.cpp / management.cpp | optimization_notifications；UI-A24 |

公共视觉沿用 Ela 原生菜单、工具按钮、输入框与文字控件，使用应用字体。新增菜单和检索的事件回调沿用宿主窗口访问屏障，嵌套 Qt 事件循环中重入关闭也须等待当前访问返回。结构截图和明暗/150% 复核属于 UI-S4；不能仅凭本分析文档视为通过。

2026-10-28：上述四项增量已实现并通过自动化、原生及本次用户新增体验确认，阶段已收口；证据见 [增量验证](ui-structure-verification.md)。分析起点及未实现独立能力的边界保留。
