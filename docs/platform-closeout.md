# Windows 平台交付收尾

## 空工作区与模块入口

工作台仍由同一宿主装配配置会话、日志、管理页面和退出屏障。启动时，显式 `--module` 优先，旧运行包邻接的模块清单兼容原默认行为。无显式模块且包内未带默认清单时，使用空模块定义进入平台工作台。两种模式均通过原配置解析、验证、应用和保存路径。

已存在的配置原文始终作为读入基线。要求外部模块的工作区在缺少模块时报告明确原因，配置文件保持原字节。平台独立启动默认使用原应用数据目录下单独的 `platform-workspace`，包含外部模块的旧运行包及显式模块继续使用原默认工作区。用户显式指定 `--workspace` 时使用所指定的目录。既有应用偏好继续使用相同位置。

空工作台可使用概览、工作区配置和开发者输出。界面继续从配置管理能力判断可添加的实例。打包由独立脚本使用已构建的 Windows x64 Release 宿主、日志查询工具、运行库和运行依赖，包及验收证据单独归档。

## 本机交付验收

验收工具将最终 ZIP 解压到本次专用目录，使用独立工作区和系统 PATH 启动 Windows 原生窗口。验证空工作台首次启动、正常关窗、配置落盘和原文件重开。查询工具独立读两次运行，检查归档终态、事件及未改变的原分段散列。额外用一个依赖外部清单的配置核对诊断及原文件保留，并可用包外通用测试模块验证显式入口。每次打包的 SHA-256、实际进程回执及模块加载位置独立保留。
