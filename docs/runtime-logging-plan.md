# 平台运行日志专项

交付目标是让开发者在下一次启动时仍能找回某个来源的一次操作、错误原因和关闭结果。平台负责采集、保存和查询。独立验收使用通用测试模块走实际装载流程，业务模块的开发和取证由其独立项目负责。[独立验收 L1–L7](../tests/acceptance/runtime-logging.md) · [工作台 UI 与交互专项](ui-runtime-feedback-plan.md)

## 当前实现与六项取舍

1. **宿主拥有一次运行。** 在解析工作区参数后、模块预检和加载前创建运行 UUID，每个进程拥有一个写入器。默认路径为 `<workspace>/.cordis/logs/<run-id>/`。工作区无法创建时，尝试在当前用户的本地应用数据目录保存启动诊断，并报告实际位置。两处都不可写时，保留有限内存记录并报告故障。Core 保持独立，运行目录、文件系统、写线程和句柄由宿主的日志组件管理。[P7 启动与关闭](../app/plugin_workbench/main.cpp)
2. **以正式接纳作为发布边界。** Qt 的即时输出、待发布输出和宿主输出在同一接纳点复制值。采集时间和来源序号可以早于接纳，调用成功可能只预留来源序号；候选回滚后序号可以有空洞。诊断消费者只收到已公开事件。替换操作失败时，由宿主记录操作结果。通知复用现有输出镜像并关联同一条日志；诊断按实际状态转换记录一次，问题视图保留按需刷新。清屏、刷新、重复读取快照都不触发写入。[Qt 输出接纳](../src/ui/output.cpp) · [通知镜像](../src/ui/notifications.cpp) · [当前问题面板](../src/ui/panel.cpp)
3. **在来源有效时复制身份。** 记录格式版本、运行及事件标识、采集 UTC、接纳次序、来源、可得模块版本、实例配置标识、运行时实例／代次、通道、级别、错误码、操作 ID 和 UTF-8 消息。未知字段留空。宿主以已注册模块、配置和真实 Context 解析身份，在实例失活前捕获所需值。后台线程只持有宿主值。平台事件只允许必要字段，例如操作种类、结果、修订和因果 ID。业务内容、凭据及完整用户路径不作为平台采集字段。对输出接口提交的自由文本，由对应模块开发者负责审查。导出提供预览和范围选择。[Context 来源](../sdk/include/cordis/instance.hpp)
4. **按运行写 UTF-8 JSON Lines，按段读取。** 每个进程独占新建运行目录和活动锁，以宿主生成的段号命名文件，后台单写线程批量追加。来源文本仅作记录值。段索引可由完整记录重建。建议起始值为每段 8 MiB，保留 14 天，每工作区最多 256 MiB，交付时用实测确认。达到大小就轮转；独立清理步骤按过期或总量移除最老的可清理段。清理前重新获取该运行的独占锁，核实归属、终态和路径，避开活动运行、未知状态、链接及非受管文件。尾部半行单独报告截断，完整行照常可查，读取过程保留故障原件。活动数据使总量暂时超出目标时，报告实际占用。
5. **写线程、降级和退出有可观察结果。** 建议按 250 ms 或批量阈值刷新，严重错误请求尽快刷新。队列按条数和字节设上限，为错误预留容量；过载按来源、时间范围和原因累计丢弃，包含高优先级记录也无法入队的情况。拒写、短写、磁盘满、flush 失败进入独立状态通道，有限内存继续服务，可以重试。部分批次失败先检查已完整提交的记录，依据事件 ID 去重，保留故障段并在新段续写。进程取消关窗时继续接纳。正常退出时，先允许 Session、Kernel、插件和 Shell 发布最后事件，再关入口、排空、写终态、flush、关文件并 join，最后释放调度器。异常退出可损失尚未确认的尾部；缺失成功终态的运行显示「结束未确认」。[现有关闭顺序](../app/plugin_workbench/workbench.cpp)
6. **分别保留 Qt 和 Native 的调用契约。** Qt `ui.output/v1` 保留原三个级别、4096 字节上限、线程及代次检查、历史快照和返回语义。Native C ABI 有五级、单条 64 KiB、每实例快照 128 条或 256 KiB，以及自身回调进入与关闭门禁。Native 适配器在合法接纳完成后将宿主持有的副本交给日志组件；释放实例锁后才进行交付，文件 I/O 只发生在写线程。五级按原意保真。持续超出旧快照限制的 Native 生产能力需要另行版本化；本专项保留已有错误码及卸载资格。旧 Qt 插件的公开结构布局保持兼容，由宿主内部补齐持久化元数据。[Qt 输出契约](../sdk/include/cordis/ui/output.hpp) · [Native 接纳](../src/module/host.cpp) · [Native C ABI](../sdk/include/cordis_abi/plugin.h)

## UI 与工具共用的查询契约

下表规定可观察语义，代码语言、函数签名及线程调度由实现阶段确定。查询只返回值、分页游标和可撤销的订阅；窗口关闭或切换工作区时取消订阅，已经排队的响应按请求代号核对归属。

| 值或操作 | 所有者与行为 |
|---|---|
| RunId | 宿主创建 UUID。运行列表返回运行起止时间、平台版本、工作区归属和状态。正在运行、正常结束、结束未确认分别可辨。排序按开始时间及 RunId 稳定打破平局。跨进程操作保留各自 RunId。 |
| SourceId | 宿主给来源分配可比较的结构化键。区分平台、插件；插件使用可得的模块 ID、插件 ID、稳定配置实例标识和通道，运行时实例 ID、代次及版本作细分条件。无稳定配置身份的实例带 RunId 与运行时身份，只能在本次运行内辨认。来源标题只供显示，不用于查找或授权。 |
| EventId 与顺序 | EventId 由 RunId 和宿主接纳序号组成，在运行内唯一，保留到段到期。原 `sourceSeq` 单独保留，因此一个较早提交、后来才公开的事件可获得较新的接纳序号。分页及订阅按接纳序号排序。UTC 显示采集时刻；实际段号和写入位置属于物理写序。64 位序号跨 JSON 边界用无损表示。可选操作 ID、因果事件 ID 用于关联。 |
| 列运行、列来源 | 按当前工作区列出本次及历史运行，按指定运行列出确有公开事件的来源，返回来源身份、已有级别和首末可用事件。平台及插件同名通道可以区分。上次运行的停用实例仍可选，来源首次出现时发布变化通知。 |
| 查询和分页 | 输入 RunId、来源或全部、可选实例／代次、级别、文本、时间范围及有界页长。第一页固定本次查询的接纳上界，返回顺序记录、下一页不透明游标和完整性提示。游标绑定运行、筛选和边界；切筛选创建新查询。已轮转的段仍可翻页，已清理的区间明确标记。禁止用时间或数组偏移充当唯一游标。 |
| 订阅当前运行 | 首次查询同时给出订阅续读位置。订阅接收该位置之后的已接纳事件与来源、持久化状态变化；查询与订阅交接支持从续读位置回放。客户端按 EventId 消除重发。消费者落后且缓冲已淘汰时显式返回缺口，可从磁盘分页补读；已经丢失或清理的范围有独立结果。后台消息不会改变已选来源，跟随和焦点属于 UI。 |
| 按 EventId 定位 | 输入完整 EventId，返回准确来源、匹配记录与邻近页所需游标，可跨会话并绕过当前显示过滤。未找到、已被清理、数据段损坏或当前持久化受阻分别说明；只有留有清理凭据时才断言「已清理」。通知指向原事件，而插件停用后的动作由 UI 重新核能力。 |
| 持久状态与清屏 | 暴露已接纳、等待写入、已写及刷新确认、持久化受阻、明确丢弃等状态及计数。刷新确认表示约定的 flush 成功，报告中说明所用系统保证。记录被淘汰、写入部分成功或存在空洞时使用范围与计数说明，单一最大序号不能证明先前全部落盘。「清空视图」只移动该视图的显示边界；历史查询、源文件及其他窗口保留。 |

记录查询对当前运行合并有限内存尾部和磁盘完整记录，以 EventId 去重。对历史运行只读完整行并返回截断或未知格式的原因；不执行历史插件，不把过期命令保存在日志中。上述契约是界面输出选择器、「查看日志」及导出的共同数据来源。[UI 消费与交互设计](ui-runtime-feedback-plan.md)

## 实施工作单

### LOG-1 当前增量 · 2026-11-26

UI 联调已经在宿主的公开接纳点写入 JSON Lines。独立验收沿用现有归档格式、运行锁、写线程、退出屏障和显示用来源。业务插件由独立项目维护。平台通过 `ui.output/v1` 接纳已发布记录，通过通用测试模块验证来源、等级和收尾，不加载任何业务插件。结构化来源元数据与统一诊断字段归 LOG-3。

模块预检由工作台记录准确阶段，并将错误分类转换成固定文案。预检失败走原启动错误与退出路径，归档记录不包含错误原文或输入路径。通用测试模块由平台的实际装载和发布机制交付受控错误记录，归档仅持有宿主复制的值。

独立验收进程以只读方式从工作区打开已经结束的运行。只读入口复用现有元数据校验、分段解析和完整行读取，按运行 ID 与接纳事件 ID 查找。查询进程不创建新运行目录或写入线程。公开 SDK 不暴露此验收入口。验收分别运行测试模块和错误清单场景，核对进程退出、来源、诊断标识和原始归档一致性。

| 阶段 | 负责改动与依赖 | 可交付结果与验收 |
|---|---|---|
| LOG-1 接纳与首个样例 | 建立宿主运行上下文、值记录、最小单写器与只读入口。在 Qt 共同接纳点连接写入器，保持候选发布门禁。宿主记录模块预检失败，通用测试模块通过公开接口产生固定错误。 | 进程 A 加载测试模块并正常退出，进程 B 于同一工作区查回同一 EventId、来源与诊断标识。另以无效清单验证平台启动记录。交错发布和回滚候选，核对可见集合。L1、L2。 |
| LOG-2 持久化、故障与恢复 | 在 LOG-1 写入器上加入有界队列、分段、运行锁、保留清理、状态观测、重试及正式关闭屏障。确定格式版本、读取未知版本和中断尾行的行为。 | 权限恢复后可续写，失败、缺口及终态可以分别核实；同一工作区两进程互不覆盖，清理保护活动运行。L3、L5，重跑 L1。 |
| LOG-3 来源接入与查询 | 基于前两阶段补齐宿主来源关联、Native 五级接入、Qt 旧接口验证、持久分页／订阅／定位，以及通知和操作事件的关联。平台在操作结果明确后记录一次，重复诊断按策略汇总。 | 无窗口读者可按来源追踪操作，跨段查历史并从订阅续读。旧 Qt 与 Native 边界记录保真。通用失败、保存冲突及恢复重试具有可关联事件。L4、L6、L7，重跑 L2。 |
| LOG-4 无界面验收 | 汇总前三阶段，使用独立工作区、真实模块、后台事件循环和两个独立进程，以查询结果、原始段和退出结果交叉核对。GUI 截图及用户提示外观由 UI 专项单独验收。 | 完成 L1–L7。保留进程身份、准确库版本、原始段、损坏副本、运行终态、事件集合和失败样本。普通读者无需连接正在运行的 GUI 即可复核归档。 |

### LOG-2 写入和清理设计 · 2026-11-26

归档拥有唯一的接纳 ID、有限的实时尾部及写入队列。队列限制同时覆盖在途批次的条数和实际序列化字节，为错误预留一部分额度。达到上限仍保留接纳后的实时尾部，单独记入丢弃数量和 ID 范围。写入器独占分段文件句柄。写入线程按 250 ms 或批量阈值提交，错误和关闭唤醒线程。平台在会话、Kernel 和窗口清理后封住入口，等待写入线程收尾，最后释放活动锁。

短写或刷新失败后，写线程保留原批次，等待退避重试。重新读取失败位置，按已知事件 ID 的原始编码核对可确认的完整记录。重新同步成功才把这些记录计为刷新确认，剩余记录用原 ID 续写。半行保留在已损坏分段，读者报告不完整末行。若半行占用下一条重试记录对应的文件名，保留原文件并移到专用故障文件名。关闭时限内仍未确认的记录进入终态计数，故障原件保留。文件刷新使用 Qt 刷新及系统文件同步，提供操作系统返回的写入确认。

清理只处理归档根下具有完整终态元数据、目录与文件身份合规的运行。进入清理前重新获得活动锁，再核对元数据和成员，避开仍由其他进程写入、未知终态、外部链接或有不识别成员的运行。按时间和容量从最早的可清理记录开始删除，保留已清理事件范围的凭据供查询。清理规则由档案组件执行，UI 只读取状态与结果。

### LOG-3 查询边界 · 2026-11-26

在同一分段扫描之上建立只读查询。历史初页捕获接纳上限，后续游标绑定运行、条件、上限和页边界。当前运行从接纳事件 ID 续读，可取消并恢复。各消费者持有自己的查询状态。归档返回数据、缺口、清理和读取状态，UI 负责焦点和显示。通知保留已有的来源序号定位路径，归档查询另外支持接纳 ID。导出使用同一快照和允许的字段。

来源选择保持插件级分组。查询可再按模块 ID、稳定配置实例标识、逻辑通道、实例代次或版本缩小范围。逻辑通道从宿主原有通道编码中取值，仅在编码中的实例和代次与已记录身份一致时去掉宿主前缀。输出面板显示当前筛选页作为导出预览。发起导出时冻结筛选和接纳上限，依同一范围导出全部匹配记录。

输出面板的来源选择按宿主识别的模块或插件分组。记录另外保留逻辑通道、已知模块及配置实例标识，独立查询可按这些字段缩小范围。导出从当前过滤条件捕获上界，面板中的同一过滤结果提供导出前检查。

Native 的 ABI 回调继续执行原身份、五级、UTF-8 和长度检查。宿主取已接纳的值和不可伪造的模块／实例身份，退出实例锁后交付给归档。受发布组约束的日志等待原提交或撤销。Native 模块层通过宿主配置的值回调转发，不依赖 Qt、归档或界面。组装层负责回调及归档的生存期。

混合工作台以配置文件所在目录作为日志工作区，并将同一个弱回调接入初始和候选 Native 会话。工作台先等待 Native 清理，再关闭窗口与归档，最后释放回调。独立 Native 命令行可继续按原装配运行。[混合工作台装配](../examples/qt_workspace/bootstrap.cpp) · [Native 会话装配](../examples/native_services/service_module.cpp)

现有支持双后端的工作台由宿主持有 Native 回调，当前和候选会话复用同一入口。回调弱持宿主。工作台为每条对外可见的记录分配现有输出序号及归档接纳 ID，Native 的原来源序号另存，五级及模块身份、代次、版本一起进入共享归档。此接线不更改模块资格、卸载或业务插件实现。

Qt 输出在现有 Context 门禁通过时复制采集时间、运行时身份和关联操作。宿主按实际运行时绑定已检查的模块及版本，发布后的稳定配置标识来自当前管理映射。待发布记录携带这些值至原提交点，撤销时随原队列销毁。旧接口签名、返回码和输出值布局保持兼容。

配置诊断来自已结算的操作结果。平台输出携带可选操作 ID 和经过平台分类的诊断码。配置失败与显式采用基线、随后重试的结果共享关联 ID。日志入口组装固定摘要、修订、分类与关联标识。原始配置、文件路径、异常原文留在现有配置交互。配置页继续用该事件定位输出。

独立查询工具由平台构建产生，只启动 QCoreApplication。它读取已有工作区的运行和来源，按接纳 ID 定位，或使用同一条件快照将记录输出到标准输出。源码层复用与界面相同的查询契约，工具进程不启动宿主或日志写入器。
