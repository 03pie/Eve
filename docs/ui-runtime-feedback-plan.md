## U11 系统外观回退的原生验收边界

工作台保管用户选择的图片与材质。Windows 高对比度、透明效果和 DWM 的返回值决定当前实际外观。设置页应在系统要求实色时准确说明原因，保留用户选项，系统恢复后自动重新显示同一张图片。验收程序使用临时 Cordis 偏好和测试图片，在同一个 HWND 中观察系统变化。每一阶段分别记录系统值、材质选项、DWM 属性、背景是否可见及窗口图。外部切换和恢复 Windows 设置由操作者控制，观察程序只读系统状态。

自动回归将系统观察与平台策略分开。Windows 适配器读取高对比度和透明效果，将两个布尔值交给工作台私有的外观更新方法。测试进程向自己的工作台传入受限和恢复状态，使用同一条材质、壁纸和提示更新路径，逐阶段记录传入值以及 Windows 实测值。外观限制仅作用于独立测试进程；公开插件接口、用户注册表和桌面主题不参与测试状态的传递。

为覆盖透明度的原生读取与消息传递，专用测试进程另用临时文件加载应用私有注册表 hive，暂将自身预定义 HKCU 映射到该 hive。持久偏好仍指向临时目录。测试只写私有句柄并仅向自己的工作台发送同步 WM_SETTINGCHANGE，正常产品路径自行创建 QSettings 和更新材质。真实桌面状态从映射前已打开的只读句柄独立采样。退出前解除映射、核对标记、关闭私有句柄并删除临时 hive。系统广播以及整个桌面的最终合成效果由真实系统切换观察另行验证。

## 通知与托管窗口的表面复核

通知中心是工作台内的弹层，背景和文字由 Ela 的弹层色提供。空通知使用独立的次级说明；已有通知使用 ElaListView 绘制条目与选中状态。窗口主题切换同时更新已经打开的浮层。平台控件保留业务名称，Ela 原生表面通过控件类型应用透明背景。实例管理、工作区配置、添加实例及模块面板沿用各自的托管窗口和材质，由原生窗口图核对表格空白区、编辑器、弹层和表单。

配置页面首次构造后会被嵌入托管窗，主题变化仍需更新其原生 Qt 控件。拖动分隔区保留原来的命中宽度，按当前 Ela 边框色显示细线，使编辑区和状态表之间的材质连续。

## 原生控件改名后的外观一致性

平台通过稳定的 Qt 对象名定位窗口、列表和输入控件。Ela 的透明背景属于控件类型；若样式以构造时的对象名作为选择器，平台赋予对象名后，视口会重新填充系统 Base 色。处理位置是实际使用这些规则的 Ela 控件，宿主保留自动化标识。委托继续绘制条目和选中态，原生容器继续提供材质。

设置下拉层还有独立的绘制边界。Ela 自行绘制圆角面板和阴影，Qt 的系统菜单底板若同时绘制，会在阴影下产生两条近白色实边。原生组合框样式负责完整面板；下拉由 Qt 继续定位并处理输入。回归比较同一 Ela 类型在默认名与业务名下的实际控件像素，核对浅深主题、各材质的设置导航、原生下拉层的前景和阴影。

窗口材质的说明由当前图片名与 Windows 实际接受情况组成，行数会随系统广播及可用宽度改变。设置行应按已经分配的内容宽度给说明预留完整高度。系统观察须等待布局处理文字变化，分阶段记录实际高度与折行所需高度，避免仅凭已更新的 DWM 状态截取中间帧。

## 应完成的三个用户任务

1. **工作区维护者处理保存冲突。** 在工作区配置窗口看见原因、当前目标和磁盘状态，审阅差异后决定如何恢复。后台收到事件时，编辑框保留选区和焦点。
2. **插件作者排查上一次运行。** 重新启动工作台，打开「视图 → 输出」，选择上次运行、插件来源和显示级别，核对实例、操作及结果。
3. **平台开发者串起整次操作。** 在「全部来源」看到平台加载模块、插件开始工作、失败或成功、退出清理。由通知或当前问题跳到准确事件，可复制本条或显式导出筛选结果。

## 拟实施的操作方式

**底部输出与问题。** 默认收起，Ctrl+J 切换开闭。页签只含「输出」「问题」。命令检索由顶栏入口和 Ctrl+Shift+P 唤起，共享平台注册的命令和权限。切换两页、调整筛选、日志追加、问题增减时保持面板高度与分隔条位置，内容在各页内部滚动。手动拖动分隔条或主窗口高度不足时调整分配。新增「视图 → 输出」「开发者：查看上次运行日志」「打开日志目录」命令。打开输出时恢复上次主动选择的稳定来源；该来源在当前运行没有记录时，显示明确空态并提供「查看上次运行」。同名插件按 ID 区分。首次收到已发布的记录才出现来源，可列出已停止实例的历史；新通道不会改变当前选择。多实例先合并在同一插件下，开发者可再选实例或代次。运行列表以本机时间、版本及正常退出／结束状态未确认区分同一天的多次启动。

```text
输出  问题       [本次运行 ▾] [全部来源 ▾] [筛选] [跟随] […]
19:32:26.104  信息  插件 A  main  实例已启动
19:33:10.208  警告  平台         保存配置失败：磁盘版本已更新
```

示意行使用拟议文案。筛选组合来源、实例、最低显示级别和关键词，可停在某一条看多行详情。刷新不打断选区或其他通道的滚动位置，暂停跟随后显示「有新记录」。历史分页向前读取，实时追加按批更新。显示级别只过滤视图。「清空当前视图」只隐藏本次已显示记录，切到历史仍可找到；「复制本条」「导出已筛选记录」显示明确范围。清理历史是设置里的独立动作，提示将影响的会话、文件大小并跳过仍在写的进程。

**提示的呈现。** 操作结果携带活动来源、严重度、事件和操作标识，由宿主决定如何呈现。通知中心按时间列出来源、摘要、已读状态和可用动作，相关日志跳转保留原会话、来源和事件位置。同一故障的重复消息在中心聚合次数；历史导入只补列表，不重新弹出。免打扰时继续留日志和未读数。只有用户主动打开中心或执行定位动作才转移焦点。

| 场景 | 屏幕反馈 | 记录与动作 |
|---|---|---|
| 编辑配置、切换选中实例 | 在编辑区显示当前草稿或选中对象 | 保留光标、草稿和操作上下文，逐键输入无需写入日志。 |
| 检查配置或应用目标 | 在操作所在窗口显示检查结果、应用进度和实际执行结果 | 同一操作标识关联开始与终态，磁盘修订在显式保存成功后更新。 |
| 保存配置成功 | 磁盘状态显示已保存及实际修订，焦点留在原控件 | 平台记录结果及修订。 |
| 配置检查失败 | 编辑区附近显示具体原因，提供返回编辑或重新检查 | 保留用户原文和上次运行目标。可直接更正的错误在当前位置反馈一次。 |
| 保存遇到磁盘冲突 | 工作区配置持续显示保存冲突、磁盘版本及可用动作 | 用户可审阅磁盘原文、载入编辑区，或采用冲突基线后显式保存。各动作说明会改变的状态；「查看日志」可定位原事件。 |
| 插件装载失败、日志目录不可写 | 宿主显示具体来源、故障及恢复入口，写盘失败显示一次持续状态 | 在插件尚未激活时由平台来源记录。诊断存储自身失败走独立反馈，避免反复写同一个故障。 |

ElaMessageBar 已有 success、information、warning、error，适合显示短提示。它的公开接口接受父窗口、标题、文字和时长。首版把「查看日志」与当前可执行的恢复动作放在通知中心和对应的平台窗口。短提示单次呈现，使用所属工作台为父窗口。持久的动作描述只保存值和命令 ID，执行前重新检查实例及代次。失效命令显示原因，历史日志仍可读。[Ela 控件](../third_party/ela/ElaWidgetTools/ElaMessageBar.h) · [当前通知实现](../src/ui/notifications.cpp)

**平台工具区往返。** 实例详情的「查看日志」带入该实例筛选，通知或问题的「查看相关日志」定位到所关联的事件。两种入口均记录触发控件和当前对象。按返回或 Esc 恢复到原平台控件、原选中项。期间若实例已退役或问题已解决，返回所属列表并说明状态。按内容区可用的 Qt 逻辑宽度分三档。宽档（≥1080）并排显示运行、来源和工具，中档（760–1079）将次要动作收进「更多」，窄档（<760）保留来源、筛选、关闭及溢出入口。跨档调整保留事件、筛选和焦点。

## 接入日志数据

输出面板读取运行和来源列表，按游标分页并订阅新记录。通知和问题条目携带事件 ID，选择「查看日志」时，工作台切换到目标运行和来源并定位该条记录。写入受阻、记录已清理和查询失败各有独立提示。日志清理由 LOG 执行，UI 显示影响范围并取得用户确认。[数据标识和接口语义](runtime-logging-plan.md)

P7 宿主以空偏好路径构建工作台，界面选择只在当前会话有效。滚动、选区和焦点由窗口持有；要在重启后恢复稳定来源、免打扰或已读标记，S7d 须为正式入口接入独立偏好文件、明确保存范围并验证写入失败的反馈。保留会话模式的宿主应显示实际生效范围。日志历史由 LOG 持久化，切换界面偏好模式不会改变归档保留期限。[P7 工作台构造](../app/plugin_workbench/workbench.cpp) · [现有偏好存储](../src/ui/preferences.cpp)

VS Code 把通道选择、显示通道和焦点控制拆开，输出视图支持过滤。通知指南建议将进度放在任务发生处、限制重复打扰。Cordis 采用现有 Ela 控件、菜单与快捷键实现这些交互。P7 正式入口一次加载一个外部模块，可用宿主启停实例产生插件事件；不同插件在同窗交错输出由既有多插件宿主覆盖。[VS Code 输出服务](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/output/browser/outputServices.ts) · [输出视图](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/output/browser/outputView.ts) · [通知设计](https://code.visualstudio.com/api/ux-guidelines/notifications)

## 实施工作单

### S5 原生实施记录

工具区的主题边界以宿主窗口和命令浮层为单位。固定页签把 Ela 颜色映射到 Qt 的背景、正文、提示和选区角色。问题树的 Win32 表头会自行绘制系统色，因此在表头、树行和详情视口直接消费相同的 Ela 颜色。菜单、下拉和命令列表项沿用各自的 Ela 控件。命令浮层以真正的外部鼠标按键关闭；组合框收起动画结束时产生的无按键焦点事件保留搜索状态。验收从同一运行中的浅色切至深色再切回，在标准材质与有背景的材质下分别检查输出、问题表头和详情、命令列表空态，以及展开的来源和筛选菜单。

原生实现把发布接纳与窗口呈现分在两个编译单元。输出服务保持同步序号和发布门；同轮连续写入合并界面更新。归档使用独立的运行与事件标识，界面定位通知时先解出原始序号对应的归档事件，复制单条和导出携带运行及事件标识。

历史按 200 条取页，窗口最多保留 1000 条历史记录。继续向前翻时只移动这段显示范围，返回最新一页重新对齐本次筛选结果。查看当前运行的旧记录时暂停实时尾部追加；归档持续接纳，导出单独流式读取整个筛选范围。

运行的来源目录为每个来源保存显示名以及实际发布过的实例、代次，每个身份只计一次。当前运行接纳时增量更新；已关闭的历史运行首次打开时用原有分段扫描同时收集来源和身份。归档复用最近一次历史目录，筛选、翻页和切换实例只改变正文查询。目录不保存日志正文。

管理和配置是主窗口拥有的独立工具窗口。从工具窗口主动查看主窗口内的日志时暂时收起来源窗口，保留它和触发控件的弱引用；Esc、Ctrl+J 和关闭面板按钮都恢复来源窗口与原焦点。这次临时显隐保留未保存的配置与管理选中行。

管理窗口的通知按钮把自己作为返回点交给主窗口右下的同一通知中心。输出与通知共用返回点管理弱窗口引用、编辑选区和所属工具窗口的临时显隐。直接关闭通知恢复管理窗口；从通知继续查看日志时把已有返回点交给输出，关闭输出后再恢复，避免中途重新显示工具窗或丢失原控件。

命令列表的注册、过滤、执行和异步结果继续由 ServicesControl 管理。列表放入工作台所有的标题栏下拉层，使用已有命令 QAction 和同一个模型。底部页签由输出、问题两个稳定页面构成。OutputControl 继续在发布成功之后接纳记录，候选记录由原有发布门控制。持久查询由归档组件提供，输出视图维护当前运行、来源、实例、级别、关键词、跟随及清屏位置；切换视图和清屏不修改原始记录。窗口仅持有返回焦点的弱引用。

### S6 / S7b 原生实施记录

通知沿用候选发布屏障、独立输出序号及有界历史。服务只接纳已发布的值；中心按来源、代次、操作、级别和正文聚合，链接保留实际输出事件序号。未读标记由接纳和实际阅读驱动。窗口内的中心、弹条和状态栏共享这份投影，后台接纳不改变焦点。工作台负责跨面板定位与返回，管理页只传递选中实例的稳定身份。添加表单在提交前给字段就近反馈，最终修订和权限仍由配置服务核对。工作区编辑器继续负责持有草稿、冲突基线及显式保存，外层窗口负责背景绘制。

同一次通知只在输出归档保存一条正文，并附上操作标识。通知中心在后台读取最近 100 条已发布通知，按运行及事件序号定位，历史项目显示日期。已读标识保存到对应运行目录，随运行一起清理。普通日志使用名为「通知」的通道时不会进入通知中心。归档故障只产生一次提示，故障说明在本次运行的通知中心持续可查。

Windows 客户区动画设置由工作台现有的系统消息观察者读取一次，同时供页面转场和平台通知使用。关闭系统动画时收起正在显示的动态消息条，后续警告沿用同一事件的状态栏与通知中心。用户所选转场单独持久化，系统恢复动画后继续使用原值。用手动调用的原生测试验证运行中变化，Win32 设置调用使用零标志，测试程序和调用脚本分别恢复并读回初值。

通用管理表格与概览卡片共用同一条草稿切换规则。编辑器持有原配置路径及修订；对象切换被拒时还原表格选区。如原对象已被外部删除，保留只读草稿，用户可复制或明确放弃后切换。

### S7d 原生实现记录

设置页面拥有分组索引、搜索词、当前分组和正文滚动区。筛选只调整可见性，宿主访问保护覆盖可能重入关闭的控件事件。目录的选择使用组键，不进入全局历史。主题、导航和面板以现有 Ela 控件的实际值为准。工作台偏好对象负责新增外观值、图片解码和独立 JSON 的原子保存。打开图片选择器前保留当前值，解码成功后一起替换图片和文件路径；关闭或解码失败保留旧值。P7 从当前用户的应用数据目录载入偏好，显式传空路径的宿主继续支持会话模式。

材质适配器检查本机高对比度和系统透明效果，并让 Ela 的 Windows 绘制分支回报每个窗口实际收到的设置调用结果。系统回退时保留用户选值。自选图片在标准材质下使用 ElaWindow 的浅深 Pixmap，在其他材质下用位于内容下方的窗口层绘制。同一宿主创建的 Ela 对话框使用同一份已解码图片。转场预览复用当前普通页面的 Ela 动效，Popup 在启动动画前提交目标页面，受控页面的呈现门禁仍在进入动画前检查。

材质切换也会让从未打开的工具窗口取得 Windows 句柄。关闭时等页面和服务释放完毕，再由主窗口在自己的 Qt 样式、焦点链仍然有效时析构直接拥有的 Ela 对话框。下拉框和列表的代理样式由控件持有，保证子视图先于样式释放。本机在两种缩放下覆盖了打开设置、选择图片、切换材质、关闭和恢复偏好。[设置导航与外观实测](../tests/acceptance/ui-runtime-feedback.md#u11u12-设置导航与外观实测2026-11-25)

### 原生概览与验收数据

设置目录由设置页面独占，分组、搜索索引与滚动位置共享同一组控件。宽窗在正文左侧列出分类，窄窗将同一目录放在正文上方。键盘方向键选分类，Enter 或空格定位正文，手动滚动时同步高亮。目录切换不产生工作台页签或导航历史。平台开关沿用 Ela 的绘制，由宿主控件向 Qt 无障碍层公开可勾选角色、当前值和切换动作，读屏与键盘、鼠标共用同一个状态入口。

首页继续消费宿主按路径或运行实例身份生成的值快照。配置实例优先显示配置中已有的实例标题，缺省时使用路径末段，第二行保留插件标识和路径。运行数取实际生命周期状态，启停开关仍表示目标值。首页与文件菜单共用添加动作，空态把同一个按钮移入提示区。页面刷新复用卡片，不重建开关或转移焦点。

跨进程 UI 验收使用正式宿主接纳的记录。归档负责运行、事件身份、历史分页和读写状态，输出面板负责选择、滚动与焦点。候选记录通过发布门禁后才进入归档。正式宿主把归档绑定到工作区，布局偏好独立按用户保存。UI-S8 分别记录这些真实入口的证据；日志系统其余保留策略、压力和运维验收沿用 LOG 工作单。

P7 的联调从「添加插件实例」创建同一外部模块的第二个实例，再用输出来源和实例筛选分别查回两次插件启动记录。联调记录同时绑定原始序号、归档事件 ID、插件来源和实例 ID。正式宿主继续加载一个用户选定的外部模块，多插件交错记录由单独的多插件验收宿主覆盖。重启用同一个隔离的用户偏好目录复核免打扰、用户卡片、材质、切页效果与壁纸。

S7d 的设置页按 Ela 示例分组，每项使用独立设置行，复用工作台的主题、导航与分隔条状态。设置页扩展现有分组索引，让同一份分组定义生成页内目录与正文。搜索和目录常驻，目录按设置页可用宽度在左侧纵排与顶部横排间切换。正文滚动更新当前组，搜索过滤后的目录与正文保持一致。设置页持有搜索词和当前组，工作台继续持有偏好值与全局导航历史。[控件、状态与后台职责](ui-workbench-redesign.md#设置页复用-ela-示例)

窗口材质复用示例的六种 WindowDisplayMode，页面切换复用五种 StackSwitchMode，分别记住选值。原生校验材质降级、切页历史与插件呈现门禁。「显示用户卡片」控制左侧用户区域，默认开启，旧偏好缺字段也显示。卡片为后续账号登录保留入口，本期实现布局与显隐，账号认证另期接入。

S7d 同时交付背景设置。用「选择背景图片」替换材质行的缩略图，从系统选择器读取 PNG、JPEG 或 WebP。整张图片解码成功后，工作台一次更新壳层与已打开的平台视图。取消或读取失败保留上一次背景。原型按会话保存背景，正式宿主沿用其界面偏好策略。单独恢复背景保留主题和材质，「恢复默认外观与布局」一并恢复背景。原生标准材质复用 Ela 的 `setWindowPixmap` 路径，其他材质由工作台在内容下方叠绘图片，Windows 继续合成系统材质。中央画布、卡片、底部面板、菜单和下拉列表、托管窗口及其控件一起做浅深主题复核。优先检查 `configuration.cpp` 的整页实色填充对材质的遮盖，以及高对比度或减少透明时的实色回退。[绘制职责与表面规则](ui-workbench-redesign.md#设置页复用-ela-示例) · [工作区配置](../src/ui/configuration.cpp)

各包采用的五个技能、对应的库实现与可复核的设计理由，见[平台 UI 设计评审](ui-platform-design-review.md)。S7a、S7b 复核字段就近报错、草稿和中文输入法；S6、S7c 复核快速连续操作与焦点返回；S8 在本机 Windows 核实读屏和系统动态效果设置。
