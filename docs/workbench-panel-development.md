# 底部工作区：命令、输出与问题

日期：2026-10-29。按用户提供的 VS Code 截图及用途选择实现。命令执行平台/插件已注册动作；输出有真实来源和目标选择；问题来自运行诊断。中央页面继续承载插件业务。

## 使用

- `Ctrl+Shift+P` 打开命令页并聚焦搜索。名称或 ID 过滤，方向键选择，回车、双击或“执行”调用真实动作。平台命令复用菜单 QAction；插件命令继续走 Context/epoch、enabled 谓词、排队执行及 Task 完成屏障。同名命令显示实例/代次，过滤后按原记录执行。面板结果区显示运行与完成/失败，执行过程另记入输出。
- 输出页右上角选择“平台”或具体插件实例/代次/通道。复制包含当前目标的全部保留记录；清空在任何控件信号发出前捕获目标并更新后台，显示期间切换目标不会误清其他记录。切换后其他目标的记录仍在。自动滚动可关闭，追加内容保留选区和阅读位置；其他目标追加记录不会重置当前视图或重建目标下拉框。
- 问题页按来源分组，展示实际启动/资源错误、缺失依赖、配置错误及命令投递受阻；支持筛选、原因详情和双击定位。每 500ms 重新读取只读诊断，恢复后移除；源不可用时保留上次结果并明确提示。相同来源/错误码/说明去重，避免实例与 effect 汇总重复计数。这里展示运行问题，不声称接入 C++ 编译器或 VS Code 的语言服务。
- 中央和底部页签的当前项透出同一内容底色，其他项使用原选中叠层。底部用紧凑页签与下划线标记；边框、主题和工具位置在 100%/150% 布局检查中验证。

## 输出接口

新增纯 C++ 源码 SDK `ui.output/v1`，见 [output.hpp](../sdk/include/cordis/ui/output.hpp)。宿主可将 `shell.output()` 作为 `ServiceOutput::of<OutputService>({"ui.output"})` 发布；插件声明对应强依赖后消费该服务，或由宿主适配器传入服务能力。

```cpp
auto output = context.consume<cordis::ui::OutputService>({"ui.output"}).value();
auto result = output.withService([&](cordis::ui::OutputService& log) {
    log.write(context, "my.plugin", "已完成实际业务操作").value();
});
```

`write` 在 owner 线程校验同 scheduler、有效 Context 和当前 epoch 后复制值。平台日志由宿主的 `ElaShell::writeOutput` 提交，普通插件不能通过通道名称伪造平台身份。`snapshot` 只返回宿主值，不含 Qt 对象、插件闭包或 Context。已停用实例的旧 Context 拒绝新写入，历史仍可查看。

全局最多 1000 条记录、64 个目标，每条 4096 UTF-8 字节，通道名最多 64 字节；超量历史/非平台目标按有界策略淘汰。显示窗口最多呈现最近 5000 行，进入 QTextDocument 之前完成裁剪，避免多行日志产生过量文本块；复制仍包含该目标的全部保留内容。插件超长记录、无效 UTF-8、控制字符通道名及非法级别被拒绝；内部平台/命令诊断过长时在完整 UTF-8 字符处截断。显示始终为纯文本。当前接口用于源码 SDK；原生 ABI 日志与 Kernel 的整体接入仍按 P4 后续计划实施。

配置工作台的 `demo.notes` 已实际写入启动记录，并注册“笔记：输出当前配置”。平台初始化、配置装配、平台动作、运行错误及保存未完成等事件进入平台输出；通知另进入其所属插件的“通知”目标，通知历史保持独立。

## 生命周期与验证

新增输出/问题刷新仅保存值及宿主弱能力，UI 写入使用现有窗口访问屏障。命令仍由原 effect 管理捕获及在途工作；关闭期间不绕过原有清理，也不把通知或投递成功当作插件命令成功。输出关闭先关写入，允许读取保留的历史。

新增九项真实 Qt 回归：`p3.panel_commands`、`identity`、`outputs`、`limits`、`problems`、`reentry`、`clear_reentry`、`output_history`、`problem_updates`，覆盖异步 Task、平台动作、同名不同实例、旧上下文/错误线程、当前目标清空、选区保留、UTF-8/容量、问题恢复及关闭重入。后三项为提交前复审新增：初次 0/3，修复后通过；命令面板执行清空的额外分支也先复现再修复。原通知和管理检查改为显式选择所属输出目标，复制/清空的工具检查通过实际后端写入，不再用直接修改只读编辑器代替数据源；没有放宽时间或生命周期断言。最终结果与日志统一见 [审核记录](code-review.md)。
