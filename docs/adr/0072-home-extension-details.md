# ADR-0072 首页插件卡片与扩展详情窗口

日期 2026-11-27。状态为已采纳。此决策更新 ADR-0071 的桌面导航与详情展示方式。

## 决策

首页承担插件浏览入口。已安装扩展、尚待恢复的引用和工作区实例共用现有 Ela 卡片。已有实例保留自己的开关与配置入口，点击卡片可查看所属扩展及当前实例。桌面扩展和没有实例的已安装扩展也能从首页找到。

详情使用工作台持有的 Ela 窗口。顶部展示图标、名称、发布者、版本和主要操作，正文展示扩展介绍、标识及当前工作区可用的管理操作。展示内容取自本地清单和真实工作区。布局参考 VS Code 扩展详情中将扩展说明与安装、管理动作放在一起的设计。[VS Code 扩展详情](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#_extension-details)

文件菜单、命令面板和首页安装入口使用同一套文件选择与预览确认流程。`Ctrl+Shift+X` 和桌面 SDK 的 Extensions 动作回到首页卡片。设置中的桌面选择复用已安装的桌面扩展以及同一详情窗口。扩展详情的打开和关闭不产生页面节点、页签或历史项。

## 所有权

宿主继续通过 `ExtensionControls` 提供目录值和变更回执，原有工作区管理服务负责实例动作。首页保存可展示的快照和稳定标识。窗口关闭、安装失败或重选卡片时，界面核对回执的目标与对象生命周期。安装状态、启用目标及真实运行状态沿用各自的数据来源。

## 对照 VS Code 的实现

VS Code 在 [ExtensionEditor](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/extensions/browser/extensionEditor.ts) 中分别构造图标与标题区、操作栏、导航和双栏内容。详情从 README 渲染 Markdown；功能、变更日志、扩展包等标签按可用内容添加。[管理动作](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/extensions/browser/extensionsActions.ts) 由安装状态、操作范围和来源决定。

Eve 延续独立 Ela 窗口，摘要与操作位于大图标右侧，标签下方的 Markdown 正文和右侧安装资料独立滚动。可执行的操作来自宿主，管理菜单复用实例配置、添加和日志入口。更新从本地文件预览，卸载继续核对已选版本的摘要。在线发布渠道和自动更新需要更新源，当前离线目录不提供这两项操作。

本地包可附带 UTF-8 的 `README.md`。目录负责验证并保存该文档，宿主在详情和预览值中提供 Markdown 与单行摘要。没有文档的旧包保留其简介。窗口使用 Qt 文本文档渲染，不执行内嵌 HTML，不自动读取外部图片。扩展包身份继续涵盖发布内容，缺少 README 的旧记录维持原指纹。此变更同时构建宿主和随附桌面；业务插件工厂及桌面 LayoutServiceV1 契约不变。

## 扩展浏览与操作

首页插件区保留现有卡片和快捷键入口，增加本地搜索。搜索匹配名称、发布者、标识和实例路径，只改变卡片可见性，实例状态仍由工作区推送。详情窗口采用 Ela 风格，标题区直接显示可执行的启用、停用、重启、恢复或卸载动作，低频动作放入菜单。详情正文与安装信息分区展示，工作区实例保留独立页签。

界面根据宿主提供的可用动作和目录元数据渲染。切换实例仅影响配置操作的目标，扩展级启停仍按当前工作区处理。新版可读取旧包和旧目录；含独立 README 的包需要新版工作台。

## 插件管理专项

对照 VS Code 源码，`ExtensionEditor` 按数据决定页签，`AdditionalDetailsWidget` 读取分类和链接，`InstallAnotherVersionAction` 将版本选择交回安装服务。VS Code 的自动更新需要可查询的发布源。Eve 的目录每个模块只选中一个版本，历史记录只保留发布指纹，早期版本可由用户提供原包重新安装。[编辑器与详情侧栏](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/extensions/browser/extensionEditor.ts) · [扩展清单](https://code.visualstudio.com/api/references/extension-manifest#marketplace-integration) · [扩展管理](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace)

- 分类、主页、源码仓库、问题反馈和许可证属于可选的发布者元数据。包预检和目录读回共用验证，发布指纹覆盖已声明的展示内容。桌面从宿主快照呈现分类与资源。旧包没有这些字段时仍可读。
- 早期目录会忽略包内已有的分类和资源声明。重新安装原包时，只有当前选中的版本、完整包 SHA-256 和旧字段的发布指纹均相符，才能在目录写事务中补全这些资料并升级指纹。保留已知安装时间；仅剩历史指纹的版本不能通过此路径迁移。
- 安装包字节数取自实际预检的文件。当前版本的本地安装时间由目录在事务中写入。两者独立于发布内容指纹；旧索引缺失的本机资料保持未知。
- “功能”展示已声明的非空默认实例配置及当前工作区已注册的页面和命令。运行贡献按工作区实例与代次归属过滤，读取值快照，不调用插件。预览仅展示可从包读取的声明，工作区实例管理保持原有入口。
- 版本选择沿用同一文件选择、预览、确认、提交和重启流程。确认时展示已安装版本和候选版本，并区分首次安装、更新、安装旧版或重装。同模块并发替换需要在目录提交锁内核对预览所见的当前包。市场统计、自动更新、预发行版和扩展合集各自需要真实的服务或清单支持，离线包继续采用显式文件选择。
- 有更新说明的扩展可随包发布 `CHANGELOG.md`。详情与安装预览共用现有 Markdown 阅读器展示“变更记录”，目录沿用 README 的大小、编码、发布身份和离线持久化规则。

官方桌面使用 `installReviewed` 一次提交预览过的文件摘要与已安装版本摘要。保留已有的 `ExtensionControls::apply` 入口，供只提供文件摘要的嵌入式宿主继续使用。两种调用共用目录安装事务。

详情窗口与首页可以同时操作。外壳刷新目录时，把同一份目录快照交给普通详情和首页，保持所选插件、页签及实例路径。安装和卸载确认沿用打开确认时的快照，操作失败由当前确认流程处理。

## 发布验证

从 0.3.0 增量打包时发现，Qt 元对象编译器可能沿用上一版的桌面元数据，而新安装清单已经写入 0.3.1。官方桌面工厂应与独立插件一样，将生成的元数据 JSON 声明为元对象编译步骤的文件依赖。宿主继续核验实际 DLL 和清单的一致性。
