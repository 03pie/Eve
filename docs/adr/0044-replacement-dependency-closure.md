# ADR-0044：以真实服务图和 Kernel 所有权计算替换闭包

日期：2026-10-31。状态：接受。前提为 [受控服务发布](0043-controlled-service-publication.md)，完整替换范围见 [P5 计划](../p5-development.md)。

## 问题与边界

停止提供者会影响已提交消费者、等待依赖的实例和子实例，仅凭插件清单或绑定数量不能确定受影响范围。原生手动实例提供的编号也不是 Core 接纳资源或 Kernel 持有实例的证明。后续替换事务必须先有可核对的实际闭包，不能由 ModuleManager 猜测 Core 内部所有权。

本段只计算闭包，不实施模块锁、停止/创建、工厂切换、状态迁移或当前代提升。配置驱动与 Session 仍持有冻结定义，后续定义事务必须一并处理这些边界。

## 决定

在既有 ServiceRegistry 的声明、父子记录、Binding 和 CommittedLease 上导出 owner 线程的纯值 ServiceGraphSnapshot。绑定记录真实提供者和活跃 committed 消费者及 epoch，并区分 Core 接纳的资源与手动原生资源；不复制服务对象、回调或调用能力。清理期间的活跃租约保留在图中，直到真实释放。

声明图包含解析后的完整 ServiceKey（名称、interface major、realm）。必需输出继续用于原有激活前环预检；可选输出另存在同一声明记录，仅在闭包快照中合并，避免改变原预检语义。已有绑定的实际提供者优先；只有未绑定的键使用潜在输出声明，不从未使用的声明覆盖宿主或另一提供者。

Kernel.replacementClosure 接受已注册 RuntimeId，以实际持有的全部未终结实例为种子，通过私有的子实例句柄检查真实树，再扩展实际 committed 边与等待声明边。Core 接纳标记仍需与 Kernel 所有权核对；闭包遇到外部消费者/子实例、开放发布组、正在转换的实例或投递阻塞时拒绝。检测联合依赖环，按消费者/子实例优先生成确定性的 stopOrder，逆序给出 startOrder。

查询不泵送调度器、不调用插件，不改变实例或目录。快照保留 instance/runtime/parent、epoch、配置 revision 和状态，但不保存配置、工厂或重建指令。它不是已加锁计划或替换成功回执；未来事务取得排他权时必须重新计算并核对，不能信任调用者可编辑的 DTO。

## 后果

Core 仍只依赖标准库和 Threads，不引用 Module、Loader、Qt 或 UI。没有第二个服务目录或生命周期机制。所有权和消费者只放在专用 ServiceBindingSnapshot 中，常规 BindingSnapshot 保持原布局与实现，不使服务调用的诊断遍历全部消费者。新增入口属于源码 SDK，宿主与同工具链 C++ 插件仍须按当前支持矩阵一起构建，C ABI 未改变。

只读查询允许尚无实例的注册 Runtime 得到空闭包；它不证明候选定义、schema 或恢复输入有效。内部子 Runtime 可以未注册，返回其实际归属供后续协调器处理，不能将子实例当作可独立挂载的顶层实例。完整替换的逻辑锁、定义协同、发布/目录整体提交与故障恢复继续在后续小阶段实施。
