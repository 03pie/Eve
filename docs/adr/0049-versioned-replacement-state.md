# ADR-0049：替换状态由实例提供、由宿主事务持有

日期：2026-11-06。状态：已接受的架构基线；尚未实现。接续 [ADR-0048](0048-host-replacement-operation.md)。具体公开类型、扩展表布局和错误码在对应实现阶段审计后确定，不能据本文宣称已有可调用接口。

## 问题与当前证据

M2c5 能重建旧配置和旧工厂，但不能还原计数器、编辑内容等运行状态。配置 schema 与状态 schema 是不同契约，不能把状态塞进 YAML 配置，也不能把重建成功写成状态恢复成功。

当前 `Runtime` 在 `instance.hpp` 中持有激活回调及不可变服务契约；真实 epoch 与资源归 `src/core/instance.cpp` 的 `InstanceControl`。原生实例由 `NativeInstanceControl` 持有，Qt 业务对象由 `QtBusiness`/`QObjectResource` 持有。Module 的 `instanceOrigins` 只证明来源，不应增加第二套实例指针或迁移对象目录。

`ReplacementScopeControl::freeze()` 关闭新业务准入，并不等待正在执行的 worker 或插件内部操作。Module 的 Call 租约保护代码驻留，不能替代业务对象的存活屏障。现有 Native RequestChannel、资源清理以及 Qt DeferredDelete 屏障仍是清理依据；不能用一个新布尔值代替它们。

## 责任与依赖

| 责任 | 唯一拥有者 | 不承担的责任 |
|---|---|---|
| 状态契约及每次激活的导出/导入参与者 | 不可变 Runtime 描述、实际 InstanceControl/epoch | 不知道模块、YAML、UI 或替换策略 |
| 本实例一致快照与新实例初始化 | 插件状态实现 | 不提交平台映射，不保存旧对象供新代调用 |
| 原生/Qt 扩展协商、调用与对象存活 | 原后端适配控制块 | 不另建运行图，不决定事务成功 |
| 导出顺序、纯值快照、候选校验、恢复及整体提交 | 原 `ReplacementOperationControl::Execution` | 不越过 Core、Module、Driver 的原账目 |
| YAML 目标、配置 schema 和落盘 | 原 Driver/Session | 不承载临时业务快照 |

Core 不依赖 Module/Loader。状态适配由后端向实际 Context 的当前激活登记，宿主通过原 Scope 的私有权限访问，普通业务不能借迁移接口绕过冻结。原始 native handle、QObject 指针和导出函数捕获不进入 ReplacementReport。

## 数据与兼容规则

状态信封包含非空 schema 标识、非零 schema 版本和独立拥有的 UTF-8 JSON 值。schema 标识最多 128 字节，每份 JSON 最多 1 MiB；事务中原始和转换后的所有有效载荷合计最多 16 MiB，复制、转换和错误路径也必须先检查预算。无状态与 JSON `null` 明确区分；不接收指针、服务句柄、QObject 或跨 DLL 的 STL 对象。

宿主复用 `src/module/json.cpp` 的有界 JSON/Unicode 检查，保持数字原文，不增加另一套解析器。Core 只维护通用值、预算和激活身份；格式与业务 schema 校验由宿主及插件实现，不引入 Core 到 Module 的反向依赖。

旧实例的原始信封一经导出就不可修改。候选校验/转换生成另一份目标信封；即使版本相同也必须验证。转换失败不覆盖原始值，恢复始终使用原始值和原工厂，而不是候选转换结果。

现有无状态插件继续采用 M2 路径。旧成员有状态且在目标中继续存在时，候选必须显式接收并验证该状态，不能因缺少扩展而静默冷启动；旧无状态、新有状态允许正常初始创建。用户目标明确删除/禁用的成员不要求在候选重建，但其原始快照仍保留到事务结束，以便失败时恢复。新成员没有虚构的旧快照。

状态属于实际成员及 epoch。根、子实例、未换代但受影响的消费者分别迁移，不能以 PluginId、路径文本或模块代次代替实例身份。动态拥有者的局部 key 只用于当次计划映射，不能授权读取其他实例。

## 快照一致性与调用屏障

导出是 owner 线程上的有界同步检查点，不允许运行嵌套事件循环、等待 worker 或调用其他业务服务。插件负责把自己的状态复制成一致值；有 worker 时使用其已有同步或已发布不可变快照。如果当前无法无阻塞地取得一致快照，返回 Busy/失败，本次替换在停止旧树前退出，不强行等待或导出半更新数据。

冻结只保证平台不接纳新业务，不承诺所有正在执行的业务已经结束。已接纳业务可以继续完成；迁移保存的是检查点状态，不承诺分布式事务或检查点之后外部副作用的回滚。各参与者不能依赖另一个成员的实时导出调用形成跨实例事务。需要跨成员一致性的插件必须由其已有业务协议提供检查点，否则拒绝本次替换。

迁移回调执行期间，实际实例必须保持存活。Core 记录当前 epoch 的迁移调用进入/退出，重入停止可立即关闭准入，但把资源释放推迟到调用返回；原生/Qt 适配同时沿自身控制块保护实际业务对象及模块 Call 引用。每次外部调用返回后重验操作阶段、epoch、取消、关闭和来源健康，不能继续使用已失效结果。Qt 对象被插件违规自行删除、C ABI 返回 PENDING、异常越界或调用结果所有权不明确时，按协议失败保留诊断与实际所有权，不能当作普通 schema 不兼容继续。

这些是待实现的保证，不是对现有 M2 屏障的额外承诺。不能只加 Call 租约后就开始调用迁移接口。

## 事务顺序

1. 原预检保留真实工厂、服务契约、定义身份和目标版本核对；读取可获得的状态契约，但不调用旧实例导出。
2. 原 Scope 冻结后，在实际成员上导出并复制旧快照。已知候选工厂可提前校验/转换。普通导出或提前校验失败时释放 Frozen Scope，旧树继续运行；关闭、来源故障或投递失败仍沿 M2 的真实清理/保留路径处理。
3. 全部旧快照成功保存后，沿原消费者先退、提供者后退顺序停止旧树。旧树未确认静止不得创建接管实例。
4. 候选在原阶段许可下创建：实际 Runtime 的状态契约验证/转换输入，实际业务对象创建后、start/activate 前导入。未导入、重复导入、导入到错误成员/epoch 或有状态成员被无状态工厂替代，均不能进入准备提交。
5. 已知工厂与动态拥有者走同一状态兑现检查。动态工厂无法在停止前取得时，由 Builder 对实际 Runtime 在激活前校验；纯 preflight 声明不能替代实际契约。其失败进入完整恢复，不能跳过校验或改为冷启动。
6. 所有成员、消费者、状态导入和旧 M2 契约均兑现后，沿原 Core/Module/Driver 原子提交；不增加第二个提交点。
7. 候选创建、转换、导入或消费者恢复失败，先按原屏障完整丢弃候选，再用旧配置、旧工厂与原始快照重建整个旧闭包。恢复失败追加 RecoveryFailed，停止闭包并保留原预约、所需代次和不确定资源；不能因“旧提供者 Active”报告恢复成功。

取消、Kernel/Session 关闭、来源故障和晚到拥有者结果复用 M2 的阶段许可及 sequence/delivery 门禁。历史结果只保留纯诊断，不保留状态回调、业务对象或工厂；正常终结释放快照预算与参与者，失败保留的原因必须能从真实账目解释。

## 后端兼容与取舍

原生使用独立、可选的版本化 C 查询扩展；不改变 `CordisPluginApiV1`/`CordisHostV1` 已有布局、capability 含义或必需前缀。状态输入只在本次调用期间借用，输出写入宿主提供的有界缓冲区；不得返回插件分配的内存或通过两次导出测长度造成不一致。扩展表必须有容量、版本、reserved 和必需函数检查，明确拒绝 PENDING。没有扩展的旧 DLL 仍可无状态运行。

Qt 使用独立 IID 的可选工厂/实例状态接口，保留 `IQtPluginV1` 和 `IQtInstanceV1` 的虚表。工厂负责契约与候选校验，业务对象负责导出/导入；状态以独立数据传递，不传旧 QObject。沿原共享 Core 身份和同工具链约束验证，Qt UI 仍 resident。

Runtime/Context 新协议若改变公开 C++ 布局或内联语义，须更新 SDK 版本并要求宿主及 C++ 插件共同重建，测试实际版本拒绝；不能仅因 C ABI 不变宣称旧 Qt 二进制兼容。具体版本变更随实现提交，不在纯设计阶段修改构建版本。

不采用给 YAML 添隐藏字段、全局 instance→对象表、把所有状态存到 ModuleManager、替换时猜测快照身份、给 V1 虚表直接追加方法等方案。这些做法混合责任或绕过现有身份/生命周期保证。现有无状态替换和真实失败保留路径继续保留，原因是兼容无状态插件和保护不确定资源。
