# ADR-0028：Home 卡片管理窗口与平台添加入口

日期：2026-10-28。状态：已实施，验证见 [开发记录](../home-management-development.md)。

## 背景

用户要求将插件管理、配置管理收进 Home 插件卡片，通过窗口打开；添加插件属于平台行为，入口放在顶部菜单。用户进一步明确，本轮添加的是已注册插件的配置实例，外部插件包导入/安装仍属于 P4。

## 决定

Home 卡片保留状态和左右启停开关，增加显式“管理”“配置”按钮，卡片主体不承担页面导航。管理窗口按实例身份或配置路径定位，复用原管理控制器、快照及权限，不创建第二个 Kernel 或另一套启停账目。配置拥有的实例仍按路径和目标修订操作，不能从手动停止/重试绕过配置目标。

管理不再占活动栏或中央页签。窗口由根工作台的 Qt 对象树拥有，关闭只隐藏；再次打开复用内容。未应用草稿保留，切换到其他对象时要求先应用或显式重新载入。对象移除后显示失效状态，不将操作转给另一实例。通知历史仍可独立查看，不因失效卡片或草稿而丢失。

顶部“文件”菜单提供“添加插件配置…”与“配置文件…”。添加表单从当前 Session 已注册定义读取插件名称，提交后完整校验并按 CAS 接受目标，不立即写盘。已存在但尚未应用的磁盘目标必须先经配置文件入口检查/应用，不能用添加操作静默覆盖。条目配置编辑只替换指定路径的 config，保留其他字段、子树、兄弟条目以及数字精度；应用、运行结果与磁盘保存分别反馈。

普通 Ui 只依赖字符串和值协议；ConfigUi 将协议适配为 Session 的校验、CAS、协调和保存。IConfigurationManagement 的新增操作提供默认不支持实现，现有来源不自动获得编辑权限。会话名称目录不返回 schema 回调或 Runtime 句柄。

完整配置文件编辑采用 PagePresentation::Dialog，继续归属 Context/epoch/effect。该展示方式不注册活动栏/中央页签，输入沿用原 epoch 门禁，退役通过 QObjectResource 删除整个 ElaDialog 及其内容，再释放工厂捕获。关闭窗口只隐藏，停用所属 Context 才撤销贡献。原有 Tab 展示、历史/搜索和禁止拖出行为保持。

## 影响

此前“没有额外窗口”的限制改为“不允许未托管窗口”；本轮新增的是受控展示方式，插件仍不能通过页面服务取得 ElaWindow 或 Kernel 管理能力。公开头不暴露 Ela 类型，Core 不增加 Qt/Ela/Loader 依赖。SDK 当前按源码兼容维护，不宣称跨版本二进制 ABI 兼容。

验证覆盖卡片定位/关闭、平台添加、重复身份/未知插件/非法负载、嵌套配置与大整数/小数保持、过期修订、磁盘冲突及恢复、弹窗贡献退役，以及管理窗口打开时重入关闭。人工确认与上一轮 UI 专项分开记录，不沿用旧回复证明新交互通过。
