# ADR-0045：Core 替换闭包的排他所有权

日期：2026-10-31。状态：已接受。基线 1cd701c。依赖 [实际闭包](0044-replacement-dependency-closure.md)，完整范围仍为 [P5](../p5-development.md)。

## 问题

只读图不能保证下一次操作时图、配置与实例仍未改变。管理入口不仅是 Kernel，还包括已有 Instance、Context.inject、原始服务发布/提交及配置协调器。异步操作也不能借用 Kernel 门面地址，或在未证明清理完成时因句柄析构而解除排他权。

## 决定

Kernel 的唯一执行账目放进私有 KernelControl，公开门面仍不可复制；异步排他作用域持有该账目，不增加第二个内核、注册表或生命周期。普通绑定快照继续使用原实现。替换闭包包含受影响子实例的实际祖先拥有单元，锁的粒度是目标 Runtime、实际实例及解析后的受影响输出键，保持其他 realm 和不冲突条目可用。

挂载分为私有初始化与开始通知/排队两步，Kernel/父实例先登记真实所有权，之后才通知注册表或调度器，防止重入关闭/替换漏掉已经创建的实例。公开门面调用先强持控制块，关闭广播遍历稳定句柄副本，不在可重入的停止中遍历可被快照回收的实例表。

ReplacementScope 是不可复制的权限句柄。取得作用域时从权威状态重新计算闭包，原子登记全部逻辑占用；已有业务可继续，但冲突的挂载、更新、重试、停止、注入和新增租约/输出不能越过占用。freeze 再核对实际选择、epoch、revision、状态及键集合，关闭旧闭包的新业务，不伪造绑定退役或撤销旧清理能力。stop 按实际消费者/子实例优先顺序等待真实清理，失败或投递丢失保留所有权，不启动后续提供者的破坏性动作。

显式 release 只在未开始停止或已证明全部静止时解除占用。停止开始后丢弃句柄保留占用及诊断；停止前丢弃可在 owner 线程撤销，错误线程须排队，撤销请求投递失败保留占用。解除后的恢复通知若失败，保留 Released 与错误，重复 release 不能抹掉错误。所有操作先强持自己的控制块，释放占用和状态后才进入可重入的调度/析构边界。Kernel.close 是关闭特权，取消替换操作的停止回执并等待全部实际实例，只有真实静止后才回收占用；实际静止证明来自 Kernel 关闭回执。

配置驱动在目标 CAS 接受前核对实际会修改/重建的条目，冲突目标不得进入期望或保存账目。未改动的占用条目只观察为 Pending，允许其他条目独立应用；预检与规划共用分类。后台恢复通过只读解除通知等待，不轮询或抢先重建。不把整个配置会话粗略锁住，实际执行仍重验 Core 门禁。停止前撤销冻结会恢复当前 Active 代的有效上下文等待者，不伪造新 epoch。

## 边界

本小阶段交付真实 Core 排他、业务冻结和有序停止，不将它报告为模块升级成功。模块当前/候选代的逻辑锁、工厂和冻结定义协同、版本/schema 验证及服务/目录整体提交仍由后续上层 ReplacementOperation 完成；状态迁移/恢复、白名单卸载和最终 H01/H02/S09 不减范围。Core 不依赖 Module、Loader、Qt 或 UI。Kernel 私有布局变化要求当前源码 SDK 的宿主与同工具链插件一起重建；SDK 更新到 0.1.1，沿用已有 toolchain.sdkVersion 精确检查，在映射前拒绝 0.1.0 声明，C ABI 不变。Driver/Session 普通关闭不越过作用域，后续上层事务须先完成或取消替换再关闭会话。实现与验证见 [开发记录](../p5-m2c2-development.md)。
