# ADR-0043：同一服务索引中的受控发布组

日期：2026-10-31。状态：接受。承接 [P5 计划](../p5-development.md)及 [固定来源安装](0042-module-artifact-installation.md)。

## 问题与选择

提供者激活完成后原先立即公开输出。替换闭包的消费者尚未恢复时，组外消费者便可能看到候选服务；仅延迟提供者激活又无法让闭包内消费者完成真实初始化。另建服务 Registry 或借用 realm 会拆开键冲突、调用屏障、依赖图和 committed 账目。

在原 ServiceRegistryControl 上增加托管发布视图，由 Kernel.holdPublication 创建 PublicationGroup，Kernel.mountHeld 使用同一索引的组内视图。Core 仍只依赖自身与 Threads，不引入 Module、Loader 或 UI 依赖。service_p.hpp 承载服务实现与 publication.cpp 共用的私有控制块，发布状态不继续堆入单个服务入口。

## 状态与所有权

- 普通实例语义不变。组内实例激活后依然为 Active，但输出从 Staged 转为 Held；默认视图和其他开放组不可查找 Held，本组消费者沿原类型/版本/能力/realm 与 committed 租约机制调用它。只读诊断仍可列出 Held，不授予调用能力。Active 不等于已对外发布或替换成功。
- 发布组是一次尝试的显式控制能力。成员登记于实际挂载路径，子实例自动继承视图；保存成员弱控制及 Core 内部就绪/停止操作，不持有 Runtime、模块对象或插件回调。成员停止、失败或消失不被悄悄从成功条件中删除。
- 组内视图保持完整键唯一性；旧 Published/Retiring 绑定未释放时，候选同键仍冲突。声明图按消费者视图选择可见提供者，实际 committed 与父子边继续使用同一张图。
- commit 先验证全部已登记成员当前 Active、业务门禁及主资源/末尾清理的交付诊断，并确认本组全部绑定为已拥有的 Held。所有输出状态在不调用外部代码的循环中改为 Published，随后才发送索引通知。
- 通知投递失败不撤回已经公开的绑定，而是保留 Published、deliveryBlocked 和错误；重复提交不能掩盖该结果。通知期间的重入提交不会提前报成功。每次操作先固定控制块，外部调度器重赋或释放原句柄不改变本次操作归属。
- abort 先冻结组内 Context/查找与调用权限，再退役输出并请求所有成员 stop。它只受理放弃，不宣称清理完成；调用方仍须等待实例 stop 或 Kernel.close。已有调用、消费者保留、资源与末尾清理沿原屏障释放，旧 committed 清理仍可调用已退役绑定及正常的外部 Published 服务。失败保留资源与非静止报告。
- 发布组句柄析构不自动提交或同步等待异步清理。组视图和绑定可保留宿主元数据；业务引用不因此保留服务对象。Kernel 为其顶层挂载登记规范索引归属，已提交组实例可正常 remount，子实例和手动挂载不会因共享组视图而被收养。
- NativeServices 的组内索引归每个原生实例保存，模块共享索引继续为规范视图。否则同一 DLL 的组内实例会把访问权限泄漏给其他实例。输出收养也核对视图归属，不能拿组外 Staged 绑定绕过发布边界。

## 范围与兼容性

本阶段是服务发布边界，不是完整 ReplacementOperation。模块/闭包操作锁、定义/配置快照与目录角色原子切换在 M2 后续接入；迁移与旧代恢复在 M3。UI 导航、命令、窗口等贡献也须在后续适配层控制可见性，Core 不把任意业务副作用当作可回滚服务输出。Qt UI 的实际页面升级和 H01/H02/S09 完整验收仍属后续出口。

新增 Held 位于诊断枚举末尾，既有值不改编号。C ABI 线协议未修改；同工具链 C++ 源码 SDK 的私有布局与辅助函数发生变化，必须重建匹配的宿主/插件，不能声称兼容历史二进制。证据见 [M2b 记录](../p5-m2b-development.md)。
