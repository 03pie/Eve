# ADR-0002：异步完成与回调投递分离

状态：W1 已实施。日期：2026-10-23。

## 问题

源任务已完成并不代表回调能够投递。调度器可能关闭或销毁，已经入队的回调也可能被丢弃。若只提供成功/失败回调，回调没有运行时，调用者可能永远等待一个没有错误出口的动作。

## 决定

- Task 的结果只完成一次，多个观察者共享不可变结果快照。
- `thenOn(shared_ptr<IScheduler>, callback(const Result<T>&))` 返回独立的 `Task<void>` 回执；源结果与投递结果不互相覆盖。
- 成功观察源错误，回执仍成功；回调抛错、投递拒绝、队列丢弃分别报告 CallbackFailed 或 SchedulerClosed。
- ScheduledJob 具有 run 和 discarded 两个入口。接受后，调度器保证只选一个；post 返回 false 表示未接受，由调用者处理失败。
- 待完成源任务中的观察者只持调度器弱引用，不延长调度器生命周期；关闭不会隐式取消源操作，待源操作终结时报告投递失败。
- 最后一个生产者退出但仍未完成的任务以 BrokenPromise 终结，不遗留无生产者的 pending 状态。
- Result 采用仅构造的分支值，禁止重新赋值；右值访问按值返回，避免产生临时对象内部引用。

## 影响

调用方需要检查投递回执，尤其是 setup/cleanup 完成通知。FakeScheduler 关闭可直接测试丢弃路径；后续 QtScheduler 必须遵循同一协议。该接口是 C++ 源码 SDK，不能直接穿越插件 C ABI。

计时、超时观察及 FakeClock 留到 W2 的清理等待功能；取消请求与任务实际终结继续保持独立。没有新增阻塞等待接口或第三方运行时依赖。
