# ADR-0046：模块预约与共同创建准入

日期：2026-10-31。状态：已接受。基线 e5e6899。依赖 [Core 排他所有权](0045-replacement-scope-ownership.md)，完整范围仍见 [P5](../p5-development.md)。

## 问题

Core 作用域拥有真实 Kernel 闭包，但模块还可从其他管理句柄或已创建的原生/Qt 定义进入。只锁 UI 或某个 ModuleManager，不能阻止另一管理器排空候选、暂存其他内容或从旧定义创建新对象；仅检查选定两个代次，也会漏掉同模块其他候选正在装载或协商的重入窗口。

## 决定

在现有唯一进程目录增加按 ModuleId 索引的预约，原子核对实际当前/候选角色、前驱、后端、插件目录、装载与失败状态，拒绝已经有业务实例的选定候选。不可复制的 ReplacementReservation 只持宿主值权限，不借用 ModuleManager 或调度器；管理器销毁不撤销它，reset/析构只解除预约，可跨线程执行。快照为纯历史值，不是执行权限。

同一目录锁统一排序预约、暂存、排空和创建准入；GenerationAdmission 跨越原生宿主协商/定义/实例、Qt 定义/业务工厂的整个同步入场过程，结束后才减计数。取得预约时检查同模块全部代次的 loading/admissions。锁内只处理宿主状态，不执行模块、调度器、QObject 工厂或清理；实际插件资源仍由原 GenerationLedger/ModuleLease 记录，不使用准入计数替代资源静止证明。

预约拒绝同模块另一预约、新定义/实例、宿主打开、暂存及 drain，含未选中的兄弟候选；其他模块可独立预约。普通 load 仍可只读复用当前代，已有业务和正常清理继续；不将 ledger.beginDraining 借作可撤销锁，避免阻断旧请求和清理。现有原生宿主 close 仍先要求托管 Core 关闭并发布 Draining，复用其状态，未引入第二套关闭账目。

## 边界

本段只提供模块级预约与真实入口准入，不改变 Current/Candidate、不执行旧实例停止、候选创建或迁移，也不表示工厂/schema 兼容已验证。后续 ReplacementOperation 须在同一控制块内持有模块预约、Core 作用域和旧定义/目标快照，先验证业务契约，再授权候选创建、协调冻结 Driver/Session 并整体提交服务/目录；开始破坏性动作后须保留这些权限直到提交或恢复结束，不能把本段可撤销预约的析构当作恢复完成。

Core、GenerationLedger、C ABI 和默认驻留策略保持原边界。完整迁移/恢复、白名单物理卸载、UI 和 H01/H02/S09、Windows 连续 100 次与随机压力不减范围，实施与验证见 [记录](../p5-m2c3-development.md)。
