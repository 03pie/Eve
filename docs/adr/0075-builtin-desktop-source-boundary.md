# ADR-0075 内置桌面的源码边界

日期 2026-11-28。状态为已采纳。

Cordis 的职责是调度实例、管理服务依赖并清理资源。此前 Qt 模块加载器写死了桌面的产品版本和标识，启动器构造了具体的日志归档，官方桌面还需要反向包含启动器私有头。将产品选择、业务实现和通用机制分别放到它们的拥有者一侧。

- `src/core` 提供 Cordis 生命周期。通用模块加载器在映射代码前校验调用方指定的模块身份、版本、文件路径和摘要。启动装配选择受信的随包模块和工作区插件。
- `plugins/builtin/desktop-ela` 拥有 Qt 工厂、激活入口、工作台、配置界面和日志业务。日志作为先于窗口挂载的内置服务，归档、查询工具、后台写入和保留策略由它维护。桌面使用同一归档，启动器通过写入句柄记录装配结果。退出时持有最后的写入句柄直至内核确认清理结果，以保留启动失败和最终退出记录。
- `src/ui` 实现业务插件共用的贡献门面。产品级桌面装配契约在 `contracts/workbench`，启动器和桌面都依赖契约。品牌资源供桌面、启动器及安装器共用。
- `plugins/builtin/workspace-extensions` 拥有扩展安装目录、包预检和实例启停操作，按 `eve.workspace.extensions` 挂载并发布扩展管理服务。启动器负责选择、挂载插件和等待就绪。已有配置页沿用 `host.configuration` 身份，作为桌面提供的插件装配。

共享构建由官方模块链接桌面实现和 `Eve::ConfigUi`。静态嵌入沿用 `Eve::Ui` 装配桌面实现，配置示例仍通过 `Eve::ConfigUi` 使用配置页。两种模式共用同一份源码。模板和独立业务插件通过既有 SDK 目标消费 UI 服务。仓库内演示可以显式复用桌面的私有 Ela 样式。

内置插件的源码、版本和随包发布由 Eve 项目维护。官方桌面可在仓库外使用与产品版本匹配的工作台开发包编译。该包提供完整桌面所用的配置库、装配头和品牌资源。桌面和启动器使用 `eve.host.desktop.v2` 协商更新后的装配接口。普通业务插件继续使用现有 SDK，第三方布局插件继续消费 `LayoutServiceV1`。随包模块沿用 `system/desktop` 布局、受保护标识和摘要验证。

启动器为每个工作台创建一个服务域。启动输入、归档、平台日志写入和扩展控制按名称映射到该域，随包的日志、扩展管理和桌面实例在挂载时接收映射。工作区业务和外部布局继续在根域消费公开的 UI 服务、调度器及布局服务。服务域只决定 Cordis 如何路由服务名，同进程原生模块仍使用同一信任模型。

### 升级已有的扩展目录

旧版允许外部插件使用 `eve.desktop.logs` 和 `eve.workspace.extensions`。读取旧目录时仍校验发布指纹、模块标识和记录结构，保留这两种冲突记录供用户按包摘要卸载。插件管理显示标识冲突并限制操作，新的包预检、安装和模块加载继续执行保留名检查。工作区中的外部模块引用按不可用插件保留，维持配置及其余实例；指向内置模块的系统插件引用继续拒绝。这样升级不需要改写用户的安装目录和工作区配置。

安装包为工作区模块别名保留 `builtin` 和 `extension`。显式 `--module` 开发清单延续旧约定，可以用这两个名字作为模块标识。两种来源都禁止冒用内置模块与插件身份，并在装载时核对同一份预检记录的模块、插件和摘要。
