# ADR-0076 桌面语言与用户配置文件

日期 2026-11-28。状态为已采纳。

VS Code 的设置编辑界面和 `settings.json` 使用同一份用户配置，移除设置后回到默认值。显示语言的更改在重启时生效。Eve 在桌面插件内采用同样的用户配置入口，已有 `session.yaml` 继续声明工作区插件实例和业务配置。

Windows 工作台从用户数据目录的 `preferences/settings.json` 读取桌面设置。嵌入宿主可指定配置文件路径。设置使用 UTF-8 JSON 对象，采用带命名空间的设置名和易读的枚举值。缺省键取桌面默认值。界面与外部编辑器共用配置文件，磁盘更新经验证后应用，窗口关闭时释放文件监听。写入采用原子替换，非法文件保留以便修复。

Ela 在同一进程共享实际主题，各窗口只保存自身的主题选择。壁纸配置保留用户选择的路径，图片加载失败时使用默认背景，用户仍可重置该配置项。

桌面以内置英文为默认。其他语言由独立的 `.evelang` 语言扩展交付。通过插件管理预检、安装、启用和卸载，复用已有列表、详情和确认流程。桌面在现有扩展控制上合并语言扩展，业务和布局扩展继续由工作区扩展目录管理。语言扩展只携带 UTF-8 JSON 翻译数据，并使用单独的 `locale.json` 保存启用的语言。

语言扩展操作在同一把目录锁下核对包摘要与选中状态。卸载当前语言时，先收起包文件，再保存英文选择。请求失败时恢复包，窗口保留已加载的文案直到重启。

桌面在创建首个窗口前安装语言翻译器。同一 Qt 进程的桌面窗口共享首个窗口加载的译文，最后一个窗口释放翻译器。控件只传稳定消息 ID 和格式参数，英文文案和启动诊断说明集中在独立的 `messages.en.json`。构建及安装将资源复制为普通文件，修改资源后重启即可生效。语言扩展以相同消息 ID 覆盖译文。缺少扩展或条目时使用英文资源，仍无记录时显示消息 ID。显示语言在重启后应用，第三方插件继续拥有自己的内容和语言。启动器提供用户数据路径，Cordis 内核无需参与语言包装配或设置解析。

VS Code 在源码中标记消息 ID 和英文，构建时生成独立的名称索引和消息表。Eve 直接维护 JSON 资源，使发行资源与开发资源采用同一种格式。[VS Code NLS 构建](https://github.com/microsoft/vscode/blob/main/build/lib/nls.ts) · [VS Code NLS 加载](https://github.com/microsoft/vscode/blob/main/src/vs/base/node/nls.ts)
