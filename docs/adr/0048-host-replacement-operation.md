# ADR-0048：由宿主持有整体替换操作

日期：2026-11-03。状态：已接受，M2c5 已实施并完成阶段审计，已随 `c8ae9a1` 提交并同步。接续 [共同定义来源](0047-configuration-definition-identity.md)与 [模块预约](0046-module-replacement-reservation.md)。

## 问题

Core、模块目录和配置账目已有各自的真实准备凭据，但由示例手动依次调用不能证明完整操作覆盖了全部拥有者，也不能保证异步失败后预约、原工厂和旧配置继续被持有。把执行流程放进 KernelDriver、ModuleManager 或 Session 会扩大已有入口职责并造成反向依赖。

## 决定

增加独立宿主库 `Cordis::Replacement`，向下依赖 ConfigReplacement 和 ModuleNative。`ReplacementOperation` 控制块独占一次执行状态，持有 Kernel、管理器、真实 Core Scope、模块预约、配置参与者和候选/恢复输入；普通 Core、ConfigYaml、泛型 Session 不依赖操作层。预检、创建和提交分别实现，低层账目继续由原拥有者维护。

预检检查计划与执行期冻结数据分开：DriverReconstructionPlan 只用于预检及回调后的来源重验；执行期配置状态只保留 DriverDefinitionChange、原目标和影响路径，恢复构造输入由拥有单元持有。目录重合并不接收整套历史执行计划。默认与自定义拥有者统一由同一个成员接纳方法计数推进；保留跨线程投递门禁和清理阶段需要的恢复模式。删除与保留依据见 [结构方案](../p5-m2c5-architecture.md)。

预检核对实际工厂的 moduleId/pluginId/代次，保留已有必供服务的类型、major、minor 与能力下限，并把配置定位文本重新预检到实际已装载文件。配置参与者必须是 Session 的真实驱动、共享调度器并处于期望修订。实际闭包、父子、输入及拥有者仍沿 Core/Driver 私有检查；纯快照和编号不是权限。

普通已登记根和显式配置子项使用原机制创建。动态子树必须提供宿主 IReplacementOwner：preflight 返回候选/恢复的纯动态成员计划，包含完整配置、realm、类型化依赖及输出；新子节点的局部 key 由宿主规范化，rebuild 按交还的完整计划创建并报告全部节点。已知工厂契约来自实际 Runtime；临时子工厂仍不被单独捕获重放，Core 同次输入捕获只追加实际纯输出声明。平台在 Prepared 后逐项核对实际依赖/输出、成员、唯一映射、父子、配置和 realm，删除未声明额外子实例仅靠祖先关系即可通过的路径。Core 入场与计划共用原描述校验/精确域依赖合并，不增加第二套运行图。 Driver 与宿主的未来服务求解同用 Core 私有 service_plan，普通配置 Pending、替换 Reject；实际外部绑定与 realm 从同 Scope/Kernel 的唯一注册表复制，预检/冻结/构建重验并驱动根创建顺序。删除 Driver 原提供者排序和宿主旧图根排序，不把声明或快照当作权限。

拥有者重建只接收绑定当次发布组的 ReplacementBuilder，替代整套 Scope。许可只保存 Scope/发布组弱引用，只提供 stage；丢弃、准备、失败或发布后关闭，旧候选许可不能进入恢复组。默认构建同样使用许可，Context.inject 沿已有组视图继承。低层 Scope.stage 继续保留给实际协调者，Core 共用组初始化并在声明准入后重验组身份，根挂载使用捕获的具体组，不能回读另一个当前组。阶段许可、关闭持有与动态纯契约的边界及剩余全局求解见 [结构方案](../p5-m2c5-architecture.md)。

逻辑配置子项已停止时，Driver 从原记录提供最近活动祖先选择，Core 在同一 Kernel 的实际图验证后复用原闭包与占用算法；私有 Selection 保留该选择供 freeze 重算，不扩大整个祖先 Runtime 的全部实例。配置祖先范围由预检与最终准备共用算法确定。宿主配置来源把旧记录 ID 与 Core 实际旧输入分开，保留单一条目映射，逻辑条目不冒充实际成员。当前已验证活动祖先及祖先也停止的重建/恢复，未证明全部未创建条目和祖先定义并发情况。

最终从最新已接受目标合并受影响属性与模块定位，保留无关条目、子树、模块和数字原文；目录只替换本次冻结的节点，不能覆盖另一模块的新目录。所有 schema、可用性、分配与准备都在提交发布前完成。持模块锁的发布段只交换 Core、模块角色及已准备的配置账目；准备阶段仍有检查和预分配。锁外解除模块预约，释放 Core 占用及通知，完成各会话和操作结果。

取消在 owner 线程立即登记，最终临界区前再次检查；已发生真实提交/恢复后拒绝取消。拥有者回调和就绪观察通过同一 owner 串行推进，晚到阶段回执不会推进另一阶段。跨线程拒投只写共享原子故障信号并终结任务，信号不持有 Kernel 或工厂；Core 的原准入门禁同时封闭，不能靠已保留的 Scope 再次创建。

Kernel 关闭复用 Core 原 closed_ 清理 Task，私有适配不发起关闭或增加状态；宿主弱观察器跨阶段有效，实际 quiescent 后才结算取消并解除预约，清理失败则保留资源，不向关闭中的 Kernel 恢复。拥有者未兑现任务的完成观察器只捕获单元索引，计划仍归唯一 Execution，终态后不由观察器延长工厂寿命。Session 单独关闭沿下述持有协议处理。

Session 关闭现接入 Loader 私有持有凭据：会话封闭业务并通知宿主，全部持有结束后才由 advanceClose 唯一入口关闭 Coordinator/Store。操作沿取消协议恢复完整旧闭包，保留其他会话及手动实例；关闭会话只有携带同一有效凭据的 Preserve 准备可通过，候选 Advance 仍拒绝。凭据观察泛型 Task<void> 结算并可在启动放弃时释放，不使 Session 依赖 Module 或宿主报告；Driver 原 stop 与 Store 保存独立证明最终关闭，操作任务失败不被当作资源静止。宿主 Kernel/Session 通知复用同一弱中断观察器，候选发布前仍读取真实会话关闭信号。 预检持有前移至实际配对与原修订核验后、Core 预约前；预检或开始投递失败由统一 abortPreparation 撤销。Core 私有释放 SPI 在原准入成功后调用宿主纯解锁，再解除 Core 占用和通知，Session 持有最后释放；不能释放时保留真实所有者并等待原 Kernel 关闭结果，不因 begin 返回错误丢弃 Module 预约。正常提交和结算同样复用 releaseClaims。

宿主在拥有者预检前取得 Driver 逻辑路径/模块别名占用，真实会话原目标通过 ConfigReplacement 桥配对，不把最后动作目标当作完整接受目标。Driver 纯权限簿独立实现并复用配置预览差异，普通执行/后台恢复/最终准备共用门禁；未创建条目不伪造执行记录。Core 复用原 Scope 与操作索引持有规范工厂读意图，原成员与显式借用共用 readsDefinition；读者可共享，但定义换代和低层新根排他须尊重已有读权限。解除 Driver 占用先于 Core 实际释放通知，不在各层再建运行图。Module 计划代次读意图通过私有 ReplacementAccess 接入原 borrowed/readers；来源只读真实 runtimeOrigins，候选 required 与恢复 original 分开记录，检查和分配完成后一起发布，沿原预约释放或失败保留。Core 规范引用不能替代该生命周期权限。

失败先等候选真实清理，再授权旧代和旧配置重建。恢复也失败时再次清理已创建的恢复成员，报告 `RecoveryFailed`，封闭创建权限并保留原始引用/预约。无法确认清理或投递时不宣称静止。准备映射归执行状态，只有真实发布时才交换到公开报告，失败报告不残留已丢弃的候选 ID。成功历史只有宿主值；执行引用在锁外释放，不留在报告中。

## 当前边界

已封存输入中未托管的 Native 服务也须有实际模块来源。Core 私有视图提供原绑定的对象/类型/提供者和阶段用途，宿主解释真实 NativeServiceEndpoint 并取得其原所有者；托管 Core 来源也由宿主转为 Module 的纯输入来源。ModuleNative 在原 instanceOrigins 中核对身份/epoch、托管属性和可选 Runtime，合入原 borrowed/readers；没有 Runtime 的原生来源用空 optional，不伪造运行节点。原 Core 私有拥有视图依赖从 ModuleNative 移到宿主，Cordis::Replacement 明确依赖 ModuleHost，Core 不反向依赖模块。

模块业务故障沿唯一代次错误与原替换预约用途通知实际操作：宿主 Execution 持有候选/恢复短期通知生产者，预约只保留弱槽，目录/信号锁外完成通知。无需为永久驻留代次建立不可撤销的观察链，也不另建全局订阅目录。冻结前和各阶段构建重验来源，最终准备复用相同用途判定；候选独有来源失效可恢复旧树，恢复所需来源失效则保留资源并报告 RecoveryFailed。原 NativeSource 对错误指针的冗余持有和两个故障入口的分散写入已删除。

当前动态来源、封存创建集合及逐成员兑现已接通，模块故障与未托管原生服务来源也已纳入原读意图/事件；整阶段审计和当前源码支持矩阵通过，本提交归档，远端同步后进入 M3。当前已验证真实 C ABI/Qt 根、手动实例、配置子项、共同提交、旧配置恢复、拥有者协议、取消重入、恢复失败保留及无关目标合并；已补两个实际 Session 的共同换代/恢复、根→子→孙动态对应、嵌套业务 DLL 子实例、遗漏成员与错误父子关系，以及独立路径下两个真实模块的并行目录提交。候选/恢复的未来输出键已在预检末尾通过真实 Scope 封存到原写权限簿，创建及服务实际入账共用检查，复用原释放路径；低层未封存 Scope 保留动态语义。已有动态成员的恢复描述必须保留 Core 捕获的原配置、域映射和规范化契约，在冻结前检查，不保留临时工厂。Core 外部绑定读意图已接入完整计划同次封存，使用原 Scope/操作目录及实际绑定，候选/恢复分开检查，不伪造消费者。主动停止/更新和另一 Core 替换须尊重读权限；真实故障/Kernel 关闭复用仅实例内部可调用的退役入口，不增加 committed 等待，并经原弱中断观察器打断悬挂拥有者。Module 实际外部托管提供者及祖先已经共用的 Core 拥有视图适配，核对原实际业务来源后合入原 borrowed/readers，不另建图或代次目录。原生主动撤回的普通读冲突已在请求/状态变化前由共用只读门禁拒绝，真实故障路径保留。动态工厂来源现由纯 ModuleFactorySource 进入冻结计划，原预约持不可变阶段创建集合并与实际代次读持有一起封存；实际 Context 在 create 前校验，Prepared 再核对成员兑现。模块生命周期读持有与插件创建权限分开，低层未封存协调兼容路径保留。多参与者部分准备失败/取消和最终支持矩阵已验证，证据见 M2c5 收口记录。该实现不等同于 M3 的版本化状态迁移，也不提供 M4 白名单卸载或 M5 UI/连续 100 次验收。
