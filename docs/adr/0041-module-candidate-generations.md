# ADR-0041：同一进程目录中的当前代与候选代

日期：2026-10-30。状态：接受。承接 [ADR-0037](0037-qt-module-boundaries.md)及 [P5 计划](../p5-development.md)。

## 问题与选择

P4 的唯一进程目录把 moduleId 视为单代身份：第二份不同摘要/版本会被拒绝。直接放开重复 ID 后，原先“找到最后一个同名记录”的搜索会让候选覆盖当前代；另建 staging registry 又会拆开映像归属、预算、失败记录和引用账目。

在原目录内区分 GenerationRole::Current / Candidate，候选记录明确保存 predecessor。普通 load/loadQtModule 继续只匹配 Current，显式 stage/stageQtModule 才可为健康当前代装载另一份内容。两个后端共用 reserveGeneration，不引入第二套目录或业务实例机制。

## 契约与所有权

- 候选入口要求有效且属于同 moduleId 的当前前驱；后端和插件目录必须一致，内容/版本必须不同。schema、服务接口及业务迁移兼容由后续替换协调完成。
- 目录锁先于代次锁，预留与角色选择在同一临界区完成；DLL query/root 构造始终在锁外。重入只看见已预留且仍 loading 的 Candidate，不能再次装载该候选。
- 相同内容的候选可跨路径/管理器复用，同一物理文件不允许冒充不同代次或模块。匹配缓存前检查全部代次的真实文件身份，失败候选也不能被忽略。
- 候选失败保留在原目录和同一账目中，不污染 Current 的状态/失败信号，也不改变普通 load 的选择。当前代失败或不再接收激活时拒绝新暂存。已知业务协商失败同样阻止候选入口使用当前前驱或复用该候选；普通发现复用仍保持原语义，不能将发现成功当作业务可用。
- 当前阶段继续使用 P4 的固定文件、受限映像映射、64 代预算和永久驻留策略；候选同样计入预算。Qt root 归 loader，业务实例归 Core，不手动删除 root。

## 范围

M1 仅提供代次并存和只读诊断角色。来源由调用方放在独立目录后重新固定/验证；hash 安装事务、运行闭包锁、候选输出发布、当前代切换及状态迁移在 M2/M3 的真实调用方接入时实现。没有提前添加 promotion、unload 或替换状态机占位接口。

测试使用真实 C DLL、Qt root、旧代业务及同步重入。临时去掉 Current 选择门禁后，两后端的并存回归均失败；逐字恢复生产源码并重建后通过。最终结果见 [M1 记录](../p5-m1-development.md)。
