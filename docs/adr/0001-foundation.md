# ADR-0001：首阶段范围与基础约束

状态：已作为当前实现基线采纳；具体实现和目标工具链验证尚待完成。

日期：2026-10-23。依据：[软件设计说明书](../../Cordis插件平台-软件设计说明书.md)。

## 决定

1. 当前目录作为产品工程根，保留现有文档；Git 忽略同步参考资料与研究仓库，不移动这些文件。
2. 第一阶段只实现内置插件内核，先完成 Task、Effect 和实例生命周期，再接服务依赖形成闭环；Qt/Ela、DLL、热替换后置。
3. core 只依赖 C++17 标准库；Qt 通过调度与资源适配器接入。
4. Kernel 采用单写 scheduler。生产宿主将使用 GUI 主线程；单测使用 FakeScheduler，不需要 QApplication。
5. Instance、Binding、Runtime、Realm、Generation 等 id 使用互不隐式转换的强类型，0 为无效值。
6. Context 按值传递弱实例与 epoch 能力句柄；过期调用失败。cleanup 获得单独的清理上下文。
7. EffectToken 为可复制控制句柄，析构不撤销；owner 保留控制块，所有 close 调用加入同一任务。
8. 停止先广播取消，再按所有权及依赖约束清理。消费者完成之前保留旧服务，不实施全局简单 LIFO。
9. mount 同步返回句柄，Pending 可作为稳定结果；业务停止和观察超时分别建模。
10. 原生模块默认驻留；C++ 源码 SDK 与 C ABI 分开设计。首阶段不冻结二进制 ABI。
11. 目标桌面版本仍为 Qt 5.15.2；本机 GCC 验证不改变 MSVC/CRT 目标基线。
12. Task/Result/Context/Effect/Instance 的实现按接口契约推进，不先导出没有行为的占位方法。

## 取舍与后续

现阶段可以在本机持续编码和测试内核，但 Qt 5.15.2 / MSVC / Ela 的产品验证仍是 P3 前置条件。Task 和 Result 不引入第三方异步框架，避免先锁定未知调度语义；自有实现必须通过重入、迟到结果及关闭测试。

改变以上决定时新增 ADR，注明受影响接口与验收场景，不能仅通过修改实现悄悄改变契约。
