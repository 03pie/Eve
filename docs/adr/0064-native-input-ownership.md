# ADR-0064 由 Native 宿主验证替换输入的服务来源

状态为已采纳。

## 背景

替换计划会冻结外部服务绑定，并对真实提供者的模块代次登记读意图。普通服务、托管实例以及直接通过 Native 宿主创建的实例具有不同的来源。过去替换操作自行识别 Native 端点，读取其实例、模块控制块和两把互斥锁。宿主实现的字段或锁协议变化时，替换层也要同步修改。

## 决策

Core 提供已封存的绑定快照。ModuleHost 通过私有函数识别其中的 Native 服务端点，在实例锁下检查提供者身份和业务状态，再单独取得模块锁检查模块状态。检查期间以强引用保活实例。普通服务返回空结果，失效的 Native 绑定返回冲突。成功时只返回现有的 `ModuleInputSource` 值。

替换操作负责合并候选与恢复所需的来源，并把结果交给已有模块预约。取得来源快照与登记读意图仍是两个步骤，后者在模块目录锁与代次锁下重新核对真实来源。错误报告沿用 `replacement.operation` 阶段。[替换操作](0048-host-replacement-operation.md) · [模块预约](0046-module-replacement-reservation.md)

## 验证

使用已有 `operation_sources_raw_loss` 回归检查真实 Native 提供者失活时的操作结算和资源保留。其余 `operation_sources_*` 场景覆盖独立来源、共享丢失与来源不匹配。
