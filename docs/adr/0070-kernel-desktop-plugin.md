# ADR-0070 官方桌面插件和运行日志的所有权

日期 2026-11-27。状态为已采纳。

## 动机

工作台直接构造 `ElaShell`，依次手工发布页面、命令、输出和通知服务。配置页捕获外壳，日志归档随窗口关闭。把外壳迁入插件后，这种所有权会导致内核退出时失去最后一条清理日志，也会让未能装载外壳的宿主失去诊断途径。

## 决策

- 宿主持有 Qt 应用、调度器、内核、工作区和一份运行日志。窗口订阅本次运行的输出。工作区的历史路径、格式和插件来源沿用既有契约。
- 内核在应用线程激活固定系统插件 `eve.desktop`。桌面实例提供现有的四项 `ui.*` 服务，就绪后再挂载配置页和业务实例。宿主专用操作通过内部接口连接。外壳与业务实例使用同一套 Core 和 Qt 服务身份。
- 先交付由内核管理的内置实现，然后迁入通过既有 Qt 工厂装载的常驻 DLL。官方模块位于 `system/desktop/module.json`，模块 ID 为 `org.eve.desktop`。安装版的业务清单和工作区选择规则独立于系统清单。系统身份不允许通过业务工作区装配、替换或停用。
- 最终将窗口、设置、导航、面板及桌面资源编入官方模块，保留发布给业务插件的 Eve 0.2.0 SDK 类型、导出符号和 ABI。产品发布版本和插件契约可以独立演进。用改造前编译的外部插件二进制做回归。
- 关闭前先保存。保存冲突保留原窗口供重试。宿主在 Qt 事件循环运行期间依次等待业务贡献、配置页、桌面和内核完成清理，确认静止后写入 `WORKBENCH_CLEANUP_COMPLETE`，刷盘后退出。失败留下具体诊断。

## 验证

使用独立无界面宿主验证纯服务实例和缺少 UI 的依赖状态。安装版验证官方模块的身份及缺失、损坏、ABI 不匹配，验证旧业务 DLL、工作区、历史日志、新装和升级。无界面宿主仅用于测试。固定官方外壳范围内无需开放第三方桌面选择或运行中卸载 Qt DLL。

初始二进制基线来自提交 `314f4cb` 安装的 0.2.0 SDK。将该版的 Notebook 测试源复制到仓库外，使用 SDK 的 `eve_add_qt_ui_plugin`、Qt 5.15.2 和 MSVC x64 Release 构建一次，记录 SHA-256 `919e45e22142b405d7c2038d18fa38fe823ef38b302b910920d259907f92017a`。旧宿主实测从页面按钮执行命令，归档中记录了 `plugin/example.notebook` 的 `SDK_020_FROZEN_COMMAND` 事件。复验时使用相同二进制和独立工作区，运行 `eve_sdk_consumer_tests <module.json> <workspace> frozen`，再用 `eve_log_query` 按来源读回事件。换工具链制作新基线时应单独记录其摘要。
