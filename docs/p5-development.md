## 必须保持的边界

- 模块目录只管理产物、代次、后端与引用；替换协调器管理运行闭包和事务。Core 不反向依赖 Module/Loader/UI。
- 候选验证不改变当前运行、期望目标或已保存配置。一个模块最多一个替换操作，配置仍可编辑，但冲突目标与管理动作不能越过锁。
- 先验证新代 PluginId、接口 major 与 schema；关闭旧消费者/提供者并确认完整清理后才启用新代。旧代未静止时不得接管同一服务键。
- 新代 staging 输出不对闭包外消费者开放；只有提供者与全部消费者实际恢复才提交成功。消费者恢复失败必须使 ReplacementReport 非成功（S09）。
- 迁移只传版本化、独立拥有的值数据，先校验后提交；不迁移 Context、QObject、裸指针、STL 对象或服务句柄。恢复使用保留的旧配置与旧工厂。
- 当前 P4 的 Windows PIN 不可撤销。可卸载代次必须在初次装载时按白名单选择独立策略，不能把历史驻留代强行 FreeLibrary。所有任务、捕获、deleter 和对象先完整释放；卸载失败仍保留诊断与所有权。
- Qt UI 当前适配器固定 resident。白名单仅向具备明确卸载契约及实测证明的后端/插件开放，不把页面关闭当作 Qt 模块可卸载证明。
- H02 必须真实完成 Windows 连续 100 次替换并核对引用、句柄/对象基线及驻留解释，不能用目录预算测试或重复预检替代。
