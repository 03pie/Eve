# UI 设计与优化专项

建立日期：2026-10-27。专项编号：UI。定位：P3 收口后的独立改进专项，面向当前 Windows / Qt 5.15.2 / Ela 工作台；P4/P5 保留原编号和范围。

工作包实时状态统一维护在 [开发进度](progress.md#ui-设计与优化专项)，本文件维护范围、设计基线、执行顺序与完成条件。[现有界面审查](ui-design-review.md)记录第一轮观察、改动和实测证据，[专项验收单](../tests/acceptance/ui-optimization.md)记录后续验证。

用户后续要求按 VS Code 每个 UI 结构分析并分阶段实施。阶段出口和顺序统一见 [专项阶段](ui-special-stages.md)，结构研究与修改清单见 [VS Code 对照](vscode-ui-structure.md)。UI-00–07 保留原范围，映射到 UI-S0–04；已通过的 Ela 基线与后续结构增量分别验证。

## 目标与交付

建立统一、可持续扩展的桌面 UI：工作台结构参考 VS Code，组件、主题和交互延续 ElaWidgetToolsExample。用户应能清楚判断当前位置、插件状态、可执行操作，以及配置是否已经应用或保存。

交付包含设计基线、公共呈现辅助、各宿主页优化、界面偏好保存、自动化行为/布局回归及原生人工验收。实施期间持续更新原 Release 目录，形成可以运行和比较的版本，不只交付静态效果图。

## 已确定的交互约束

- 全局左侧是插件活动栏；单击打开对应中央页签，子页可在打开前后选择。资源树属于具体插件页内部。
- 保留顶部菜单、页面搜索、前进后退及现有快捷键。所有中央页签可关闭，包括概览；零页签时中央为空白。
- 底部命令/输出默认收起，Ctrl+J 或面板入口按需打开；通知不主动展开底部区域。
- Home 保留品牌横幅及 Ela 卡片展示。插件卡片只展示状态并提供单个左右启停开关，不增加打开跳转或悬浮导航。
- 状态、可用动作及失败原因来自真实快照。主题切换、刷新、布局恢复不发起插件启停或配置应用。
- 配置编辑、接受目标、实际运行、磁盘保存和外部冲突分别表达；恢复操作不得隐式丢弃编辑或覆盖磁盘。

以上约束来自已确认需求，后续工作包在此基础上细化。

## 视觉与布局基线

下表是本专项的设计目标，实施时通过真实内容与缩放验证。尺寸使用 Qt 逻辑像素，不将其当作物理屏幕像素。

| 项目 | 基线 |
|---|---|
| 空间 | 使用 4/8px 间距体系；工作页面外边距通常为 20–24px，相关控件间距 8px，内容分组间距 16–24px |
| 文字 | 正文 13–14px，次级说明 12–13px，分区标题 14–18px，页面标题 24px；Home 品牌标题可单独扩大 |
| 字体 | 按用户补充要求统一使用 ElaApplication 的应用字体（当前 Microsoft YaHei），图标采用 ElaAwesome；配置文本也继承 Ela 字体，不另切换系统等宽字体 |
| 层级 | 每个操作区只突出一个主要动作；次级/恢复操作降低视觉权重，危险操作有明确文字和作用对象 |
| 颜色 | 使用 Ela 主题与语义映射；普通/次级文字对比目标至少 4.5:1；状态必须同时有图标或文字，不只依靠颜色 |
| 控件 | 常用按钮高 30–34px、数据行高 32–36px；图标动作提供名称、提示和键盘入口 |
| 卡片 | 当前插件卡片基线宽 280px、最低高 144px；随容器换行，长名称/状态通过换行或省略与完整提示处理 |
| 弹性 | 内容优先自适应，必要时滚动或省略；不通过压缩文字高度容纳固定卡片，不限制用户可调整的页面分隔条 |
| 编辑 | 配置文本继承 Ela 字体并保留四空格制表宽度，长行可水平滚动；文件路径与状态信息不挤占主要编辑空间 |
| 主题 | 深浅主题下容器、编辑器、表格、菜单、焦点、悬停及禁用状态协调一致，主题切换不丢失页面状态 |

appearance_p.hpp 是第一方视觉与键盘辅助；组件、页面和适用范围已由 UI-00 记录在 [设计系统](ui-design-system.md)，不要求外部任意插件遵循第一方呈现。已有卡片尺寸与默认交互在没有实测原因时保持。

### UI-00：规范先于批量替换

先盘点现有 Ela 组件及第一方封装，再抽取间距、文字层级、主要动作和状态呈现。页面差异应有理由，避免每页重新配置同一套颜色/尺寸。组件优先使用公开接口；只有组件自身无法满足合理需求时，才单独评审第三方本地补丁。

本轮既有菜单/搜索、Home、配置分区和设置页修改纳入 UI-01/UI-02/UI-04/UI-05 的起步交付。已有 Release 432/432、最终 UI 92/92 和截图为历史基线，不代表上述完整工作包已经完成。

### UI-03/UI-04：状态表达

插件状态的图标、文字和颜色由真实状态枚举及操作状态产生，不解析现有中文状态文本。真实启用状态与当前是否允许操作分开表达；失败或忙碌时不能把开关误显示为关闭。

配置至少分别呈现编辑是否应用、运行目标是否稳定、保存是否完成和是否存在磁盘冲突。应用成功不显示为保存成功；磁盘通知只提示变化，显式载入、采用基线和保存保留各自含义。错误详情包含原因与下一步可执行动作，面向用户的主界面避免直接堆叠内部账目。

### UI-05：偏好与业务配置分离

界面偏好采用独立、有版本的宿主存储，不混入插件 YAML 或业务 ConfigurationSession，不保存 Context、epoch、InstanceId、页面工厂及运行对象。值要校验并限制到当前屏幕/控件可用范围；恢复布局不得触发启停、应用或写业务配置。

只恢复主题、导航模式/宽度和面板高度；每次启动底部仍收起。不在本专项中增加页签会话恢复、拖出窗口、多编辑器分屏或新的模块能力。偏好写入失败应给出可理解的反馈，工作台仍可使用。

## 实施顺序

1. UI-00 盘点并固定基线，复核第一轮 UI-01/UI-02/UI-04 改动及用户体验反馈。
2. 优先完成 UI-01/UI-02/UI-04 的主要工作流，同时推进 UI-03 管理与诊断，统一状态呈现。
3. 完成 UI-05 的设置/偏好；UI-06 的键盘、长文本和缩放检查贯穿每轮，不集中拖到最后。
4. UI-07 对两个桌面入口联合回归、人工验收、代码审查，归档后再登记专项完成。提交按用户指令执行。

不以重排编号或修改 P3 历史结论启动专项；P4 的 ModuleManager/ABI/驻留和 P5 的受控替换仍按原架构路线推进。专项没有承诺完成日期，进度按实际交付更新。

## 实现边界

样式和宿主交互主要落在 src/ui，插件页保留内容所有权；普通 Ui 不增加 Loader 依赖，配置专用呈现留在 ConfigUi。公开插件 SDK 继续隔离 Ela 类型，Core 不因界面优化引入 Qt/Ela。

页面撤销、工厂/捕获释放、窗口关闭、异步退出及物理资源屏障继续遵守已有契约。仅新增视觉辅助时不改生命周期协议；增加偏好 I/O 或交互状态时提供对应失败和重入验证。sources/ 保持只读，研究副本不进入产品构建。
