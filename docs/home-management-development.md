# Home 卡片管理与配置实例添加

日期：2026-10-28。对应用户本次“插件管理和配置管理收到 Home 卡片、窗口打开、顶部菜单添加插件”的增量需求；不重新编号已验收的 UI-S0–S4。本轮代码及上一轮尚未提交的 Ela UI 改动一起进行提交前审查。

用户已明确添加范围为“添加已注册插件的配置实例（先完成现有能力）”。不包含插件包安装、DLL 加载或 P4/P5 模块能力。

## 使用方式

| 入口 | 行为 |
|---|---|
| Home 卡片左右开关 | 沿用真实加载/停止/重试，配置条目仍操作期望目标 |
| 卡片“管理” | 打开并定位此对象的 Ela 管理窗口；手动实例可停止/重试，配置实例展示实际状态及配置归属 |
| 卡片“配置” | 进入此配置路径的 YAML/JSON 编辑，应用与保存分开；手动创建、未接入配置会话的实例禁用并解释原因 |
| 文件 → 添加插件配置… | 从已注册定义选择类型、填写唯一实例标识及配置，点击“添加并应用”；目标接受/运行失败/被替代分别反馈 |
| 文件 → 配置文件… | 打开完整平台 YAML 的托管窗口，保留预览、应用、保存、磁盘冲突和显式恢复能力 |

管理与配置不再占全局活动栏或中央页签。配置工作台启动进入 Home；插件自身业务页面仍从活动栏打开到中央。默认底部收起和全页签可关闭保持。

管理窗口复用同一个后端，固定实例或配置路径；关闭只隐藏，不停止插件、不丢草稿。未应用草稿时切换管理对象会提示，需先应用或明确重新载入。旧对象失效时禁用动作，通知历史仍可打开。没有配置会话的入口禁用平台添加，不提供无效果的可点击按钮。

已有磁盘配置尚未接受为目标时，添加操作提示先从配置文件窗口检查/应用，以免丢失原文件条目。新目标不会立即保存；显式保存和正常退出沿用已有 Session/Store 策略。

## 实现与审查

- home/workbench/pages：卡片入口、菜单能力状态、移除全局管理导航，以及宿主配置文件回调。
- management：单对象窗口、固定身份与编辑草稿、平台表单、来源能力/修订校验、异步回执及独立保存。
- configuration_management：将添加/修改/保存适配到真实 Session；默认不支持的来源不获得隐式编辑权限。
- Loader：读取已注册名称，受限值树精准替换/追加配置；不经浮点 JSON DOM 重编码其他插件数据。
- PagePresentation::Dialog：复用原 Context/effect 和 QObjectResource 完整清理，窗口不进入导航，也不替代插件停止。

架构边界见 [ADR-0028](adr/0028-home-management-windows.md)。只读 sources/ 和第三方库不修改；第一方控件和字体继续来自 Ela。

审查修复了深色编辑器白底、旧管理导航测试假设、配置草稿被动切换风险、失效对象影响通知入口，以及普通 JSON DOM 可能舍入其他插件大整数/小数的问题。运行失败不伪报为已启动，保存冲突不伪报成功；已有未应用磁盘目标不能被添加操作覆盖。

## 本机入口

仍在原目录运行 build/ela-msvc-release/bin/cordis_config_workbench.exe。通过 --file 指定独立文件可体验“添加 → Home 卡片 → 管理/配置 → 保存”；未存在的独立路径从空配置目标开始。已有正式文件尚未应用时，先从顶部配置文件窗口检查并应用。
